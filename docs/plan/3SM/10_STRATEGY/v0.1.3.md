# v0.1.3 — Data-landscape map: availability & spec access across sources

## Abstract

Strategic refocus (2026-09-12, user direction): before any sizing or
sampling, the study needs a general map of the data landscape — what
is available from which source, at what scale, and with what access
to specifications. Deliberately coarse ("don't go into detail");
legal references and legal data are of no concern in this unit
(D27/D28 discipline, sharpened here). The unit answers the two study
questions as measured floors per source — **Q1: how many products
under HS 3208/3209 can we identify** (observed listings; the 3213
artists'-colours annex rides along in the same walks, D13) and
**Q2: for how many of them can we get the specifications (SDS/TDS-type
documents) needed for analysis** — and assembles them into one
cross-source availability map. The sampling-frame apparatus
(stratification, precision targets, seeded draw), the config-file
migration and the full historical trade import move out of this unit,
deferred until the map shows where a frame is worth building.
Under D30 (user ratification 2026-09-12) the deliverable headline is
the three-number triad — see "The three numbers" below; everything
else stays but is not the focus.

## Scope

In:

1. **Channel enumeration (PE):** complete the site lists per channel
   taxonomy (DATA_SOURCE §PE: manufacturers, CH/EU DIY chains, B2B
   portals, marine/art shops) with inclusion criteria and
   provenance; the register grows only through this documented,
   capped step (W6) — caps pinned per D30: MFR ≤12, CH-DIY ≤4,
   EU-DIY ≤5, MARINE ≤5, ART ≤6; B2B carried OPEN (no confirmed
   portal). This is the main lever on the Q1 floor.
2. **Census-walk extension to enumerated sites:** polite
   `products_listed` / `doc_links_seen` walks (v0.1.2 mechanics,
   depth ≤ 3, page budget) — the measured Q1 floors and the Q2
   access evidence.
3. **Coarse register priors (best-effort):** SPIN (ST-2) preparation
   counts, PCN (ST-1) formulation-count aggregates, PRODCOM (ST-3)
   producer counts — manual or light imports, recorded as
   provenance-cited findings or documented-blocked; no deep
   extraction pipelines.
4. **Coarse trade context:** latest available year of CS-1/CS-2
   flows per HS heading (CH + EU27) — volume context only, one
   compact line per source (grain rule W2); the 2019–2025 import
   pipeline defers.
5. **The data-landscape map (deliverable):** per source — what it
   offers (product listings / formulations / trade rows / spec
   documents), scale (x), spec access (y), constraints (robots,
   paywall, manual, blocked) — one matrix + compact per-source
   blocks, every number provenance-cited; aggregate lines: sum(x)
   as an observed floor (floors are lower bounds; budget-limited
   walks are annotated as such), sum(y) — CH/EEA split where a
   source supports it.
6. **Frame-decision bridge:** on the measured floors, a short,
   evidence-cited recommendation where a sampling frame is feasible
   and where it is not — the input contract for the deferred frame
   unit.

Out (deferred or other workstreams):

- Sampling frame, stratification, seeded draw, precision targets —
  deferred to a later unit once the map justifies them.
- Config file + migration (D21/U2 deferral stays open); make
  variables keep working.
- Full historical trade import (2019–2025).
- SDS acquisition, parsing, lead screening (M2); corroboration (M3);
  analysis (M4). No paid sources (D9). Legal texts and legal data
  stay out of the unit entirely (D27/D28; user direction
  2026-09-12). HS 3213 stays a census annex inside the same walks —
  no separate sample design in this unit.

## DECISIONS (unit-level; authoritative list in MASTER.md)

- W1: the unit's deliverable is the data-landscape map answering Q1
  (products identifiable under the HS headings, per source — an
  observed floor, never a market total) and Q2 (spec/SDS-type
  documentation reachable, per source). Coarse, general, no detail.
- W2 (D28 grain rule): trade rows are volume context, never product
  counts; one compact context line per trade source.
- W3 (D20): counts become `population_anchor` rows only via a
  recorded manual promotion citing run_key; never automatic.
- W4: aggregation = floor summation across sources with stated
  overlap caveats (cross-listing between channels is not dedupli-
  cated here); ranges only where cheap; no estimation machinery.
  Aggregates sum completed (done-run) sources only; blocked, failed
  and not-yet-walked sources are excluded from the sum and counted
  in the aggregate line. The bottom-up × top-down estimate method
  defers to the frame unit.
- W5: SPIN/PCN/PRODCOM enter as best-effort context priors
  (documented-blocked acceptable); SPIN's lead-CAS incidence stays
  the pilot prior (D8) but is not extracted in depth here.
- W6: register growth only via documented channel enumeration
  (inclusion criteria, cap per channel, provenance); no ad-hoc
  site additions.
- W7: every number provenance-cited (run_key / manual record);
  `db audit` exit 0 on the corpus.
- W8: the unit ends with the frame-decision bridge — a short,
  evidence-cited recommendation where a sampling frame is / is not
  feasible — the handoff to the deferred frame unit.

## The three numbers (deliverable — user ratification 2026-09-12, D30)

- **N1 — market size:** how many individual paint products are on the
  EU market under HS 3208/3209. No official product registry exists
  (REACH registers substances, not products); anchors: ECHA PCN
  statistics (unique hazardous-mixture notifications), CEPE industry
  structure, PRODCOM producer counts. Manual records on ST-1/ST-3.
- **N2 — total data pool:** how many products we can get ANY data for
  = Σ `products_listed` over the enumerated register (walk floors).
- **N3 — detailed-data pool:** how many we can potentially get
  DETAILED data for = Σ `doc_links_seen` (SDS/TDS reachable), per
  channel.

Everything else in this strategy stays but is not the focus (user
directive 2026-09-12). The 2026-09-12 seed-register census is the
baseline, not the deliverable: 3 done (CS-2, PE-1, PE-4) / 1 blocked
(PE-2, coop 403) / 3 failed (CS-1 TLS wall, PE-3 placeholder,
ST-2 timeout); `db audit` clean.
