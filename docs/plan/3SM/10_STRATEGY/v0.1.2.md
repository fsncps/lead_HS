# v0.1.2 — Census close-out: full source probing, structured source reports, operator layer

## Abstract

First real use (2026-09-11) exposed two gaps. (1) The probe census is
incomplete and its parameters unproven: CS-1 failed fetch, CS-2
export_rows=1 (suspect query), ST-2 fetch failed, PE sources probed
at landing pages only, manual sources (ST-1 PCN) unrecorded. (2) The
report layer shows a fragment — no per-source run status, no summary
matrix, and the decision-maker's questions (records per source, HS
breakdown, data availability) are not answerable from it. This unit
closes M0: it completes the census for every register row, structures
all source metadata, and delivers md/csv/json reports — built on the
operator layer (repo-root `Makefile` as the stable entrypoint, CLI
operability fixes, explicit report routing) and delivered through it
(`GO=1 make census`). Source metrics measure feasibility; product and
lead measurement stays M2+ (stated in the report itself). Strategy
decisions: D21/D22/D25/D26 in `MASTER.md`.

User review of the first full report render (2026-09-11) reframed the
report product-first (MASTER D28): the census answers the two study
questions — products available (observed floor) and products with
reachable SDS-type documentation — with trade rows demoted to volume
context and the register slimmed to product sources (CS/PE/ST;
migration 0004). U9's "feasibility-only" framing is superseded by
U11–U13; mechanics (single assembly, md/csv/json, R4, GO=1) are
unchanged. Census execution (PHASE07) follows the rework on the
user-approved go.

## Scope

In:

1. Census completion (execution + minimal fixes — no new pipeline
   stages):
   - register/URL fixes: CS-2 parameterized API query; ST-2 download
     page; CS-1 export mechanics documented as findings.
   - PE catalog-level probes (`catalog_count`, `category_count`,
     `sds_sample_ok` on real catalog pages, not landing pages).
   - manual records: ST-1 PCN aggregates, PE-3 deferral note.
   - blocked/failed sources documented with run status + notes.
2. Metric additions where required (migration INSERT per the metrics
   extension rule — relaxes this unit's earlier "no new migrations"):
   per-HS record counts (3208/3209/3213) as explicit metric codes
   (Design decides: U10/OD-A).
3. Report content layer: per-source structured sections — identity /
   access / content (format, granularity, coverage, languages) /
   counts (records, per-HS where applicable) / availability
   (`page_sample_ok`, `sds_sample_ok`) / provenance (runs, documents,
   timestamps) — plus a cross-source summary matrix; run status and
   notes visible; honest titles ("source feasibility"); md + csv +
   json from the same data.
4. Operator layer: repo-root `Makefile` (GNU make): one target per
   `leadhs` call; composite targets (`setup`, `probe`, `census`)
   orchestrate existing CLI calls; `make help` is the
   self-documenting index. Pipeline parameters as make variables with
   documented defaults (`DB`, `MODE`, `SAMPLE`, `SOURCE`,
   `REPORT_DIR`, …); a committed config file is deferred to M1 (one
   config migration, not two). Explicit confirmation gate `GO=1` for
   costly operations (`probe`, `census`) and destructive ones
   (`clobber`) — operational form of the census go-ahead discipline.
   Report routing: `data/report/` intermediates; `make
   report-publish` stages into `docs/report/` (committed). CLI
   operability fixes (see requirements below) — small, contained,
   testable against the existing fixture site.
5. Housekeeping that rides along: `.gitignore` additions (`build/`,
   `.pytest_cache/`, `.benchmarks/`); README "Using the tool" section
   (plain language, per documentation conventions) with real census
   numbers, covering both install paths (strategy D24): repo
   `make install`; peer `uv tool install` from the release wheel.
6. Register slim (D28): `sources.csv` keeps product sources only
   (nine rows); migration `0004__product_census.sql` removes the
   LG-*/LI-* rows and any runs/findings/documents recorded against
   them, adds the `products_listed` / `doc_links_seen` metrics, and
   redefines `v_anchor_candidates` to include `products_listed`.
7. Product-first probe metrics (D28): PE category walk (BFS,
   depth ≤ 3, page budget ≤ 12 incl. homepage) emits `products_listed`
   (distinct product detail links) and `doc_links_seen` (SDS/TDS-type
   links) alongside the existing sample metrics; per-category
   `category_count` keeps the path in notes (R4 strict); CS-2 per-HS
   parameterized counts unchanged.

Out (milestone-gated, stub targets that exit 1 with a pointer):

- `frame`, `sample`, `acquire`, `ingest`, `parse`, `analyze`, `full`
  — M1–M4 (ARCHITECTURE.md rollout). No new `leadhs` commands, no new
  pipeline stages; the only migration is metric additions where
  required (In item 2). Lead/product measurement stays M2+.

## DECISIONS

- U1: Makefile is the operator entrypoint; thin wrapper — pipeline
  logic gravitates into the CLI as milestones land (strategy D21).
- U2: Parameters are make variables until M1; defaults documented in
  the Makefile header; every run still records its parameters in the
  DB (strategy D2 unchanged).
- U3: `GO=1` gates `probe` and `census` (all active sources, real
  network); `probe-single` and `probe-dry` stay ungated.
- U4: `clobber` requires `GO=1` plus an interactive confirm — it
  deletes the evidence database.
- U5: Report routing per strategy D22; `report-publish` copies, never
  moves, and reminds that committing is explicit.
- U6: Milestone-gated stubs fail loudly (exit 1, one-line pointer) —
  discoverable, never silently wrong.
- U7: `make install` stays the repo-developer path (editable
  install); the peer/external route is the standard wheel via a
  managed interpreter (`uv tool install`/pipx) from a GitHub release
  asset — strategy D24 / ARCHITECTURE D10; no public PyPI footprint.
- U8: v0.1.2 closes M0 — the delivered census is this unit's
  deliverable, executed through the operator layer (strategy D26);
  supersedes the census-first/v0.1.2-first sequencing discussion of
  2026-09-11.
- U9: the census report presents structured per-source metadata plus
  a cross-source summary matrix (strategy D25); framing text
  distinguishes source-feasibility metrics from product/lead metrics
  (M2+).
- U10 (→ Design/OD-A): per-HS counts as explicit metric codes
  (migration INSERT; avoids v_probe_latest (source × metric)
  shadowing) vs deferral of full HS breakdowns to M1 frame extraction
  with probe-level representative counts only.
- U11 (supersedes U9's framing; keeps its mechanics): the report is
  product-first per MASTER D28 — the two numbers lead, one matrix,
  execution log, per-source blocks, legend; access metadata appears
  as one compact line per source; run documents/findings counts stay
  in json only.
- U12: register product-only (CS/PE/ST); LG/LI leave the tool via
  migration 0004; legal/literature context stays in 10_STRATEGY
  documents (D27/D28).
- U13: product-count metrics `products_listed` / `doc_links_seen`
  (PE walk; R4 strict — numerics carry no value_text; category path
  stays in finding notes); `v_anchor_candidates` extended with
  `products_listed`; anchor promotion stays manual (D20).

## Operator workflow (target)

    make install          # pip install -e .  → `leadhs` on PATH
    make setup            # + db init + source load + doctor (idempotent)
    make probe-dry        # plan the census; zero network
    GO=1 make probe       # census close-out (D26; polite, multi-minute)
    make record SOURCE=… METRIC=… VALUE=…   # manual PCN findings
    make report           # md/csv/json → data/report/
    make report-publish WHICH=data/report/probe-report.md
    make db-audit         # provenance R1–R9 + orphan check

Set `LEADHS_CONTACT` in `.envrc` (direnv) — doctor warns when unset.

## CLI operability requirements

1. `source list` registered once (no `list-` artifact).
2. Uninitialized DB → guided error ("run `make setup`") in `db
   status/audit`, `source load/list`, `probe run/record/report`;
   never `bug: no such table`.
3. Exit codes: click usage errors → 1 (convention i1); run-blocked
   stays 2; audit violations stay 3; interrupt 130; `SystemExit`
   preserved.
4. Bare group invocation prints help (pinned, deterministic).
5. Minor: drop no-op `--no-net` on doctor; unused imports; `.gitignore`
   additions.
6. README "Using the tool" section, plain language (conventions in
   AGENTS.md).
