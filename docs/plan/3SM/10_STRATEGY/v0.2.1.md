# v0.2.1 — Source-level sounding-out of the expanded universe

## Abstract

v0.2.0 mapped the web channels (N1 anchors, N2 = 204,693 sitemap-visible
product URLs across 23 counted sources, N3 = 9 sites with a visible SDS
library). The numbers unit succeeded, but a product URL is not yet a
product. The next step (user direction, 2026-09-13) is **v0.2.1**, which
stays at source level and expands the register: add the official-register
sources (ecolabel/EPD), the CS/ST/AS/LI additions, and enumerate the PE
universe. For each source it records a **capability profile** against the
study's product model — **(CN8 code, manufacturer, manufacturer
product-ident)** — plus the catalog volume and data depth. This tells us
which sources can actually deliver a real product (not a marketing
variant) and at what scale, **before** v0.3 seeds the normalized product
DB. No DB seeding, no scraping in this unit.

The strategic finding that shapes this unit (2026-09-13 research): **no
official EU chemical register publishes product-level paint data
publicly.** ECHA PCN is authority-only; SPIN/KemI/national registers are
substance-level with confidential product names; EuPCS is a taxonomy with
no CN8 mapping. The official *product-level* sources that do exist are
the ecolabel/EPD registers — EU Ecolabel (ECAT), Nordic Swan, Blue
Angel, INIES, IBU, environdec — each a certified/declared subset of the
market. These give clean manufacturer + product-name lists without
scraping, and are the seed for N2. The complete product list still needs
PE catalogue expansion (deferred).

## The capability profile (per source)

| Field | Question it answers |
|---|---|
| `products_identifiable` | How many products does the catalog feature? (volume) |
| `manufacturer_field` | Can we break it down by manufacturer? |
| `product_ident_field` | Is there a manufacturer-internal ident / licence no. / UFI? |
| `cn8_linkage` | Can we map to the 13 CN8 codes? (category / PRODCOM / EuPCS proxy / manual) |
| `depth_tier` | (1) name only · (2) name/ident + some technical · (3) deep technical + manufacturer-internal docs · (4) standardized specs + IATA/CMR MSDS |
| `access_method` | CSV / API / export / web — and terms |

This is the "is a product URL actually a product" test: a source that
yields (CN8, manufacturer, product-ident) at depth ≥ 2 is a real product
source; one that yields only a name is not.

## Scope

In:

1. **Source expansion (register growth):**
   - **Official product-level registers** (new AS rows): EU Ecolabel
     ECAT, Nordic Swan, Blue Angel, INIES, IBU, environdec.
   - **CS/ST additions:** PRODCOM (DS-059358), national statistical
     offices; PCN aggregate, SPIN, national product registers.
   - **AS:** CEPE member list, national paint associations (VdL DE,
     FIPEC FR, …), ecolabel bodies.
   - **LI:** studies, IPEN.
   - **PE universe enumerated** (CEPE ~800 members → each manufacturer's
     site; DIY chains; marine; art) — enumerated and characterized,
     **not scraped**.
2. **Per-source capability characterization** — record the profile above
   for each new source. Official exports/APIs (ecolabel CSV/API, PRODCOM
   API) are legitimate reconnaissance (D3), not scraping.
3. **CN8 breakdown objective** — for each source, record whether we can
   reach the 13 CN8 codes and how (category mapping, PRODCOM
   correspondence, EuPCS proxy, manual inference).
4. **Preliminary N2 numerator estimate** — sum of
   `products_identifiable` over sources that pass the (CN8, manufacturer,
   product-ident) test; a floor, with the honest caveat that official
   registers are subsets.

Out (deferred):

- Seeding the product DB (v0.3).
- PE catalogue scraping (v0.4).
- SDS acquisition/parsing/lead screening (M2).
- Frame/stratification/draw (later unit).
- Legal texts (D27/D28). Swiss market metrics (D31).

## DECISIONS (unit-level; authoritative list in MASTER.md)

- U1 (source-level): v0.2.1 is source-level reconnaissance only — no

- U2 (capability profile): per source, record `products_identifiable`,
  `manufacturer_field`, `product_ident_field`, `cn8_linkage`,
  `depth_tier`, `access_method`.
- U3 (official exports = recon): official exports/APIs (ecolabel
  CSV/API, PRODCOM API) are legitimate reconnaissance (D3), not

  characterized, not scraped (deferred to v0.4).

  inference.
- U6 (provenance): every number provenance-cited (run_key / manual
  record + URL + access date); `db audit` exit 0.

## The product model (the test target)

- **CN8 code** — one of the 13 codes under 3208/3209/3213.
- **Manufacturer** — the company that actually produces the formulation
  (not the retailer/private label).
- **Manufacturer product-ident** — the manufacturer's own product/article
  code (the primary identity key, MASTER D33); UFI (regulatory
  formulation ID) and GTIN/EAN (retail) recorded as cross-reference
  identifiers.

## OPEN ITEMS (unit-level)

- EuPCS↔CN8 mapping gap: no official mapping; treat PC-PNT-2 as an
  approximate proxy for CN 3208/3209 with explicit caveats (method
  decision).
- PRODCOM↔CN8 correspondence table: retrieve the official Eurostat
  correspondence document.
- SBS 20.30 live values: API response-size limit; use the Data Browser /
  bulk download.
- 3208 90 11/13 polymer-threshold wording: confirm against the current
  CN year (EUR-Lex Reg. 2658/87 as amended).
- Ecolabel register granularity: ECAT CSV column layout; Blue Angel XLS
  export; Nordic Swan CSV export; per-register paint counts to confirm.
- INIES API auth: registration required (email + apiKey + read
  permissions) — confirm whether the web search suffices for recon.
- SPIN Access DB download: page timed out in research; confirm live
  availability and data vintage (suggests 2020).
