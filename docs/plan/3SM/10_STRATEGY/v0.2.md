# v0.2.0 — Market scale & data availability (the numbers unit)

## Abstract

Strategy turn (2026-09-12, user direction — MASTER D31): the next
minor version delivers **numbers, visibly**. Two headline quantities:

- **N1 — how many paints are on the EU market** (HS 3208/3209): an
  estimate in magnitudes and ranges, assembled from official
  statistics — trade volumes, production, notifications, product
  registers, industry structure. Not sparse tables: the report must
  state the order of magnitude with method and provenance.
- **N2/N3 — data availability for them:** how many products we have
  access to in some form (register/dataset access, sitemap-visible
  listings), and for how many we can get detailed data / an MSDS —
  counted where sources expose counts, characterized at
  reconnaissance level elsewhere, honestly flagged where only a
  scraping go can measure.

Method bounds (D31): no scraping — reconnaissance only (robots/terms,
API/download endpoint checks, sitemap product-URL counts via a single
structured fetch, manual-web); catalog walks stay deferred until an
explicit go. Market scope is EU-only; the Swiss market is of little
concern and Switzerland stays the regulatory frame only. Source
discovery is first-class: a new source class **AS — associations &
registers** (CEPE + national association member lists; national
product registers with public statistics) joins the activated
count-bearing ST rows. HS 3213 demotes to a low-priority annex
(D13 superseded). This unit supersedes the walk-based execution of
v0.1.3 (FROZEN; walk machinery stays built but idle) and inherits its
od8 report layer and probe mechanics unchanged.

## Scope

In:

1. **Official-statistics assembly (N1 backbone):** CS-2 Comext
   aggregation — fix the adapter to persist the raw JSON and sum
   rows, kg, supplementary units and EUR per HS heading (3208/3209;
   3213 context), latest year first, partner tops in notes (API
   calls, not scraping). PRODCOM/SBS (ST-3) NACE 20.30: production
   value, number of enterprises, persons employed — recorded as
   manual provenance-cited records. PCN (ST-1): verify whether ECHA
   publishes formulation-count aggregates; record or
   document-blocked. SPIN (ST-2): preparation counts per use
   category + lead-CAS incidence (pilot prior, D8) — Access-DB
   download, not scraping.
2. **AS-class source discovery:** CEPE and national paint
   associations (member counts, industry structure), national
   product registers with public statistics (Swedish Products
   Register/KemI strongest candidate; DK/NO/FI equivalents to
   verify) — identified, access-characterized, added as register
   candidate rows; counts recorded where publicly available.
3. **Reconnaissance characterization of web channels:** per
   enumerated PE source — robots/terms status, API/download
   endpoints, sitemap presence and product-URL count (one structured
   fetch, counts only, no URL harvesting), SDS-library visibility on
   landing pages (manual-web), constraints (JS-gated, 403).
4. **N1 estimation assembly:** triangulation of the assembled
   statistics — bottom-up (producers × products-per-producer ranges;
   association member counts), top-down (trade tonnage/value bounds,
   notification counts, register counts) — reported as ranges and
   orders of magnitude with stated method and assumptions; clearly
   labeled as an estimate; EU27/EEA scope.
5. **N2/N3 access assembly:** per source, an access tier —
   (a) register/dataset access (counted), (b) sitemap-visible
   (counted at reconnaissance), (c) visible but uncounted without
   scraping (characterized), (d) blocked/unknown (flagged) — plus
   the access-decision bridge: per channel, what a scraping go would
   buy and what it would cost.
6. **The numbers report:** numbers-first layout via the existing od8
   layer (md/csv/json): N1 range up front, N2/N3 totals with tier
   composition, per-source table, trade context line, access-decision
   bridge, legend; every number provenance-cited (run_key / manual
   record with URL + access date).
7. **Register changes (migration):** EU-only slim — CS-1 and CH-DIY
   seeds leave; AS rows enter; recon/AS metrics added
   (`sitemap_products`, `sds_library_visible`); CS-1/CH rows pruned
   like the D28 slim.

Out (deferred or other workstreams):

- Catalog scraping, BFS walks, per-product collection — deferred
  until an explicit user go (D31); the walk machinery stays built but
  idle.
- SDS acquisition/parsing/lead screening (M2); frame/stratification/
  draw (later unit, behind the bridge); config-file migration
  (stays deferred).
- Legal texts and legal data (D27/D28). Swiss market metrics (D31).
- HS 3213 beyond a low-priority annex (V7).

## DECISIONS (unit-level; authoritative list in MASTER.md)

- V1 (numbers-first): the unit succeeds when the report shows
  magnitudes — N1 as a stated range with method, N2/N3 as counted
  totals with tier composition. Characterization tables without
  numbers are an incomplete deliverable.
- V2 (N1 method): triangulation of official statistics only — trade
  volumes (Comext), production (PRODCOM/SBS), notifications (PCN),
  register counts (SPIN, national product registers), industry
  structure (CEPE/associations); ranges and orders of magnitude, no
  false precision, clearly labeled as estimate.
- V3 (access tiers): "access in some form" includes dataset/register
  access; tiers (a)–(d) above; sitemap counting is reconnaissance,
  URL harvesting is collection (deferred).
- V4 (D31): no scraping — reconnaissance only; walks defer to an
  explicit user go; the v0.1.3 walk machinery stays built but idle.
- V5 (EU-only): CS-1 and CH-DIY seeds leave the register; channel
  caps MFR ≤ 12, EU-DIY ≤ 5, MARINE ≤ 5, ART ≤ 6, B2B OPEN.
- V6 (discovery first-class): AS candidates are identified and
  characterized before any activation; register grows only through
  documented candidate rows.
- V7: 3213 is a low-priority annex — worked only if free capacity
  (D13 superseded).
- V8: every number provenance-cited (run_key / manual record + URL +
  access date); `db audit` exit 0.
- V9 (tool discipline): no new pipeline stages or CLI commands; the
  unit rides the od8/probe mechanics; changes are the register
  migration, the CS-2 aggregation fix and recon/AS metrics.

## The three numbers (large-numbers emphasis — user direction)

- **N1 — paints on the EU market (estimate):** orders of magnitude,
  anchors on file (METHODOLOGY.md): EU27 extra-EU trade €1.1 bn in /
  €4.3 bn out, ~860 kt (2023, Comext DS-045409, CN8 sums computed);
  ~3,200 EU27 producers (NACE 20.30, Eurostat SBS 2019–20); CEPE
  ~800 members ≈ 85% of €17 bn; PCN/register counts when verified.
  Reported as a range (the 10⁴–10⁵ formulations hypothesis is the
  working frame) with the assembly method stated.
- **N2 — products we have access to in some form:** Σ over counted
  tiers (register/dataset counts + sitemap-visible counts), with
  tier composition and honest "unknown until go" flags.
- **N3 — detailed data / MSDS reachable:** counted where sources
  expose it (register/statistics counts; SDS-library visibility at
  reconnaissance); per-channel access-decision for the rest.
