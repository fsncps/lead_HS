# v0.2.4 — Management CSV sample (registry fields & cross-identification, manual check)

## Abstract

User direction (2026-09-14): after the v0.2.3 benchmark extractions,
the question is what the benchmark registries actually return per
registered product item, whether items can be cross-identified as
individual products across two or more registries, and whether any
registry carries a unique product-identifier column that matches a
column of another register. The manual check: download, per registry,
a list of 100 random 3208/3209 product items with all available data
fields as CSV for management review. Unit v0.2.4 delivers this as a
new probe command (`leadhs probe download-csv-sample`) plus the
generated per-registry manifest.

## Research findings (2026-09-14 evidence pass)

The blunt finding: of the five registries in the v0.2.3 summary, only
one publishes product-level rows publicly at all.

1. **EU Ecolabel ECAT** (36,960 official 03/2025; our staged 17,838) —
   YES: monthly bulk CSV + API (pinned export URL, AS-2). Fields per
   product item (pinned from the v0.2.1/W1 ingest + the ECAT user
   manual's extract column table): product name
   (product_or_service_name), licence holder (company_name), licence
   number (licence_no), product group (group_name), product code
   (code_value — EAN13/GTIN, often missing: measured identity
   completeness 16.0%), ECAT-internal product/company IDs, company
   country, validity dates.
2. **ECHA PCN** (1,444,290 dossiers 2021) — NO: the PCN database is
   restricted to member-state appointed bodies (login/eDelivery);
   companies see only their own submissions
   (poisoncentres.echa.europa.eu, accessed 2026-09-14). The PCN
   format per dossier is documented (UFI, trade name, EuPCS use
   category, hazard class, labelling, pH, composition CAS/EC,
   packaging) but not publicly retrievable — out of reach under the
   cost constraint.
3. **Swedish poison centre / Echo** (71,231 paints/coatings 2022) —
   NO: the underlying KemI Products Register is secrecy-protected at
   product level ("normalt inte ut uppgifter om enskilda produkter");
   public access is aggregates only (KemI-stat) (kemi.se, accessed
   2026-09-14).
4. **Danish Produktregistret** (≈40,000) — NO: aggregates only via an
   embedded Power BI report (v0.2.3 PHASE02 shape gate); CKAN
   resources have no download URL.
5. **Eurostat SBS** (3,300 enterprises) — not a product registry
   (enterprise statistics, NACE C2030); no product items exist.

## Cross-identification (answers)

- Across these five: NOT possible today — cross-identification needs
  at least two registers publishing product rows; only ECAT does.
- **ECAT's EAN13/GTIN (code_value) is the only public unique
  product-identifier column in the set**, and no other register of
  the five publishes a matching column.
- The PCN's UFI would be a unique key but is not public in any
  register; its realistic join partner is SDS Section 1.1 (the D5
  join key for later corroboration).
- Licence numbers (ECAT vs Nordic Swan) are different schemes — no
  join.
- Realistic paths: ECAT ↔ Nordic Swan (name + licence holder; EAN
  overlap to be checked — the pending second-register pilot), and
  ECAT EAN ↔ retail/manufacturer catalogues (the e-retail matching
  the Commission describes on the Green Forum retailer page — EAN
  matching is the intended mechanism). The latter is the v0.3
  seeding path.

## Scope

In: the new probe command (six-registry default target set: AS-2,
AS-3, ST-1, ST-3, ST-6, ST-7); per-registry CSV samples where
product rows are publicly obtainable (ECAT; Nordic Swan if its
export mechanics yield); the generated manifest; probe_run/finding
records. Registers carry no CN8 codes — the in-scope filter is the
category mechanism (ECAT group-044; Nordic Swan criterion 096).

Out (unchanged): product-DB seeding (v0.3); any scraping beyond the
official exports (D31); SDS acquisition (M2); no new staging
measurement rows — the samples are review artifacts, not measurement.

## DECISIONS (unit-level; D36 is the Master-level record)

- **S1 (command):** `leadhs probe download-csv-sample` — probe-native
  (D7/D18/D20 discipline), not a script, not a new run mode.
- **S2 (target set):** the five benchmark registries + Nordic Swan
  (AS-3) — the second-register candidate; the four non-sampleable
  registries get honest no-product-rows manifest records (the
  manifest itself demonstrates the data landscape).
- **S3 (draw):** seeded, reproducible (--seed, recorded in run + CSV)
  per the D2 seeded-sampling discipline.
- **S4 (routing):** CSVs + manifest → data/report/ (D22); publishing
  to docs/report/ stays an explicit act.

## OPEN ITEMS (unit-level)

- Nordic Swan (AS-3) export mechanics (GET vs form-POST; JS-bound
  search surface) — the command attempts bounded discovery and
  records an honest failure; the browser pass stays the fallback.
  **Real run 2026-09-14: the discovery delivered** — the pinned
  search surface serves a CSV at `?format=csv` (9.8 MB, text/csv);
  2,283 filter hits → 14 distinct items drawn. Trial-grade (ragged
  unquoted-comma rows, mixed EU Ecolabel/Nordic Swan licences, no
  dedicated identifier column) — reconciliation stays in TODOS.md;
  the browser pass is no longer the primary expectation.
- Exact public ECAT export header — re-pinned by the first real
  sample run (the full column list lands in the manifest). **Closed
  2026-09-14:** the 12-column header matched the v0.2.3 staging
  exactly (17,838 in-scope rows reconciled; 17,013 distinct after the
  identity-triple dedupe).
