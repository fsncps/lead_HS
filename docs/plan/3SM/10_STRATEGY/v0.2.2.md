# v0.2.2 — Product-identity and granularity sounding-out (the three-question funnel)

## Abstract

v0.2.1 built the source-level capability machinery (six probe metrics,
probe_mode `capability`, `ASAdapter`, capability report) and measured
it on ~1 of ~10 capability sources, producing a single numerator
(17,838, ECAT). v0.2.2 (user direction, 2026-09-14) **improves on
v0.2.1's goals and methodology** without pulling v0.3 forward: probe
the data landscape deeper — no product-DB seeding, no scraping — and
report the answers at the granularity achievable without pulling large
datasets and documentation.

It answers three questions under the study's future definition of a
**Product = manufacturer + manufacturer-internal ident number**:

- **Q1 — pool (per CN8, approx):** how many individual products are
  known on the EU market through statistical bureaus, trade statistics
  and registers, and how many for each CN8 tariff position?
- **Q2 — identifiable (counted floor):** how many of these can we
  potentially identify **definitively** (manufacturer + ident + detailed
  product info)?
- **Q3 — SDS reachable (modeled reach):** for how many of these will we
  potentially get an SDS for download?

Two enablers from the user direction make this materially deeper than
v0.2.1/v0.2.0:

1. **Runtime budget.** Earlier probe runs completed in <5 min; the user
   set the acceptable range at 30–60 min (maximum a few hours) for a
   run with good data. This unlocks real export ingestion (ECAT CSV,
   Nordic Swan export, PRODCOM bulk), per-CN8 / per-member-state
   queries, a SPIN extraction attempt, and far wider robots-compliant
   recon — all still reconnaissance (D3 official exports over
   scraping; D31 recon-only).
2. **Test-data DB allowed.** "No product-DB seeding" does not preclude a
   **test-data database** for this and coming test runs. We use it to
   make the compiled numbers re-derivable (see U4), without starting to
   scrape and crunch.

The epistemic status of each answer is labelled: **Q2 is the only hard
count**; Q1 and Q3 are explicit models (estimate / reach estimate), so
the study's honesty signature holds. The v0.5 sample-vs-pool ratio is
precisely Q2 ÷ Q1; v0.2.2 delivers the first honest version of both
components.

## The funnel (the core new concept)

| Question | Definition | Epistemic status | Primary source |
|---|---|---|---|
| **Q1 — pool** | Products known on the EU market, per CN8 | **Modeled estimate** (stats count tonnes/€/enterprises, not products) | Comext per-CN8 + PRODCOM↔CN8 + SBS/CEPE producer counts + observed products-per-manufacturer |
| **Q2 — identifiable** | Products definable as (manufacturer, identnr) + detail | **Counted floor** | Official product-level registers, deduped union |
| **Q3 — SDS reachable** | Products for which an SDS (or equivalent standardized spec) is obtainable | **Modeled reach** | SDS-library recon × manufacturer-match rate; EPD registers = standardized-spec download for ~100% of entries |

The capability profile from v0.2.1 continues unchanged (six metrics);
v0.2.2 **completes its measurement** across the register rather than
deepening the concept.

## Scope

In:

1. **CN8 trade table (N1 refinement).** For every CN8 code under
   3208/3209 (3213 as annex): extra-EU imports (kg, €), exports,
   intra-EU flows (verify the flow codes in DS-045409), production via
   the official PRODCOM↔CN8 correspondence (approx), member-state
   breakdown (the declarant dimension already present), and an
   observed-products-per-CN8 floor derived from register category
   mapping. CN8 verification is **not** a hard requirement (U6); the
   breakdown is as good as the correspondence + category proxy allow,
   with caveats.
2. **Product-identity counts (Q2).** Per official register: entries,
   distinct manufacturers, distinct (manufacturer, ident) pairs,
   identity completeness, category distribution. A **deduped union
   across registers** with a measured overlap coefficient (the ECAT ∩
   Nordic Swan pilot) → "definitively identifiable: N".
3. **Depth-matrix completion (Q3).** Every source with `cap_depth_tier`
   + identity fields + linkage; counts per tier (the 4-rung ladder);
   per-PE-site SDS document-URL counts (sitemap-derived); EPD registers
   recorded as the standardized-spec downloadable class (tier 4
   equivalent).
4. **Pool model v0 (Q1).** Products-per-manufacturer distribution
   (register licence-holders + wider recon) × producer counts (CEPE
   ~800 primary; SBS NACE 20.30 = 3,200 as the wider bound) → a per-CN8
   pool **range**, method explicit.
5. **Source expansion & census (U8).** The register grows to its full
   census shape (see below); the PE universe is **enumerated** (rows at
   `active=0`) at full breadth, with the probe caps re-derived from the
   new runtime budget.
6. **Test-data staging DB (U4).** A separate `data/testdata.sqlite`,
   populated **only from archived documents** (the automated probe path
   already archives every fetch), each staging row carrying `source_id +
   document hash + retrieval date`. Staging product rows: manufacturer,
   ident + ident type, name, category, raw fields. Makes the compiled
   numbers re-derivable and grounds the v0.3 schema in real data.
7. **Provenance repairs (from the v0.2.1 review).** ECAT manual records
   re-cited with the export URL + access date + the 16,001/1,817/20
   breakdown; the unrecorded environdec claim recorded-or-softened;
   LOG defect note for the HTML-mis-parse incident; the v0.2.1 strategy
   doc frozen (a separate action, flagged here).

Out (deferred):

- Product-DB seeding / the normalized manufacturer + product tables
  (v0.3) — no pulling forward.
- PE catalogue scraping (v0.4).
- SDS acquisition / parsing / lead screening (M2).
- Frame / stratification / draw (later unit).
- CN8 code-list verification — softened to a metric, not a gate (U6).

register censuses the universe; probing stays budget-capped and
recon-only.

## The product model (the identity triple)

- **CN8 code** — one of the codes under 3208/3209/3213. A metric for
  the identity DB, **not** a hard verification requirement (U6).
- **Manufacturer** — the company producing the formulation (not the
  retailer/private label).
- **Manufacturer product-ident** — the manufacturer's own product /
  article code (primary identity key, D33); GTIN/EAN (retail) and
  licence/registration numbers recorded as cross-reference identifiers.

## DECISIONS (unit-level; authoritative list in MASTER.md)

- **U1 (unit shape):** v0.2.2 improves v0.2.1's goals and methodology;
  probe the data landscape deeper; no product-DB seeding, no scraping
  (D31); no pulling v0.3 forward.
- **U2 (the funnel):** three questions Q1/Q2/Q3 under Product =
  manufacturer + identnr; Q2 counted, Q1/Q3 modeled, labels explicit.
- **U3 (N2 split):** N2a = web visibility (URL floor, context) vs N2b =
  identified products (official registers, counted) — the real metric.
- **U4 (test-data DB):** separate `data/testdata.sqlite` staging store,
  fed only from archived documents (source_id + doc hash + retrieval
  date); not the product DB.
- **U5 (runtime / cost cap):** default 60 min probe budget (override
  flag), per-wave budgets, resumable per-source; recon-only,
  robots-compliant; official exports/APIs are legitimate reconnaissance
  (D3).
- **U6 (CN8):** code-list verification is a metric, not a gate; N1
  broken down by HS as good as the correspondence + category proxy
  allow, with caveats.
- **U7 (provenance):** every number provenance-cited (run_key / archived
  doc hash / URL + access date); `db audit` exit 0; staging rows carry
  the document hash.
- **U8 (source expansion):** register expands to its full census shape;
  PE universe enumerated (`active=0`) with probe caps re-derived;
  enumeration ≠ probing.
