# Unit v0.1.1 — source probing (slim CLI)

## Scope

First bounded work unit: build the probe-era slice of the `leadhs` CLI
and run the source census with it. No product ingestion, no sampling,
no SDS parsing — probing tools only. Delivers:

1. `leadhs db init|status` — probe-era schema subset (`schema_version`,
   `source`, `probe_run`, `probe_finding`).
2. `leadhs source load|list` — source register seeded from a repo CSV
   mirroring DATA_SOURCE.md.
3. `leadhs probe run --source ID | --all` — per-source census probing:
   counts (catalogs, categories), access constraints (robots/terms/
   rate limits/languages), format checks (swiss-impex export, SPIN
   extraction path), sample pages as raw evidence.
4. `leadhs probe report` — census summary: counts per source, access
   constraints, candidate population anchors.

## Why this unit first

The strategy's open empirical questions (EZV/swiss-impex granularity,
population triangulation inputs, SDS corpus quality) are exactly what
a source census answers. Probing is the Phase-0 instrument: it
converts OPEN register rows into verified access metadata and
provisional frame inputs before any sampling design is frozen, and it
de-risks the pilot — access constraints discovered now shape the M2
scraping plan.

## Method fit (condensed)

- Probe counts are **provisional** frame inputs; promotion to
  `population_anchor` / `frame_stratum` is a manual method decision
  (MASTER D20).
- Probing obeys DATA_SOURCE.md scraping discipline (rate limits,
  robots/terms, official exports preferred) — light by design.
- Legal-text verification (LG class) stays a manual document workstream,
  outside probe scope.

## Milestones (project-wide rollout; this unit = M0)

- M0 — probe (this unit): db + source + probe → census + anchors.
- M1 — frame & sample: `frame set`, `sample plan`, `sample draw`.
- M2 — acquire & parse (pilot on 1–2 strata, lead driers first; then
  full n): `acquire run`, `ingest sightings`, `parse sds`, `review`.
- M3 — corroborate & analyze: `corroborate`, `analyze prevalence`.
- M4 — report: `report build` (DE/FR/EN), database freeze.

## DECISIONS (unit-level; authoritative list in MASTER.md)

- U1: slim scope — probing tools only; the full command surface stays
  design-ahead (ARCHITECTURE.md), implemented per milestone.
- U2: probe-era schema subset migrated first; remaining tables land
  with their milestones (probe results may reshape frame/sample
  entities).
- U3: census counts recorded per source (and per catalog category
  where exposed); category→stratum mapping is a frame decision (M1),
  not a probe decision.
