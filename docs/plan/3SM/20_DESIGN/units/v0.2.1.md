# Unit v0.2.1 — Design delta: source-level capability sounding-out

## Abstract

The Design for unit v0.2.1 (strategy `10_STRATEGY/v0.2.1.md`, the
D33 source-level expansion). v0.2.0 counted *what a source exposes*
(sitemap product URLs, SDS-library visible). v0.2.1 must answer, per
source: **is an entry actually a real product per the study's model —
(CN8 code, manufacturer, manufacturer product-ident) — and at what
volume and depth?** That is the "is a product URL a product" test. The
unit expands the source register (ecolabel/EPD registers, PRODCOM and
national statistics, CEPE/national associations, enumerated PE
universe) and characterizes each source against the model — capability
profile, volume, data depth, CN8 linkage — then assembles a
preliminary N2 numerator. Reconnaissance only (D31): no product DB
seeding, no scraping.

The design principle: the capability profile is **measured, not
declared** — it is the result of inspecting what a source actually
delivers. So it rides the existing `probe_finding`/`probe_run`/
`v_probe_latest` machinery (the recon precedent, nu1), as a set of new
probe metrics under a new probe_mode. No new entity, no new pipeline
stage, no new CLI command (V9).

## ENG review (2026-09-14, mode HOLD SCOPE)

Findings A1–A2, C1–C3, folded into the design/implementation plan
before build:

- **A1 (capability run surfacing):** `report._fetch_latest_runs`
  hardcodes `mode_code IN ('census', 'recon')` — a capability run
  would never surface as a source's latest run. Folding it into
  that clause would also perturb the existing tier logic
  (`_tier_of`/`_counted_value`). The capability matrix therefore
  fetches its **own** latest-`capability` run per source, leaving
  `_fetch_latest_runs` untouched.
- **A2 (N2 numerator coexistence):** the preliminary N2 numerator
  (Σ `products_identifiable` over real-product sources) is a
  separate derived line labeled "N2 numerator (official registers,
  floor)" with the certified-subset caveat; it never feeds
  `_counted_value`/tiers or the existing N2 sum.
- **C1 (ASAdapter shape):** `ASAdapter` matches `class_code=='AS'`
  and no-ops (returns empty) for `mode != 'capability'`, so the
  census/recon sweeps are unchanged; the register shape-inspect
  logic is a reused helper, not inlined.
- **C2 (one tuple):** a single `CAPABILITY_METRICS` tuple (the six
  codes) drives the capability-matrix columns and predicate
  derivation — no duplicated literals.
- **C3 (one predicate helper):** a single
  `_is_real_product_source(by_metric)` implements the predicate;
  tested once against each failing axis (manufacturer=0,
  product_ident=0, linkage='none', depth<2).

Resolved at review: **cap5 → new `ASAdapter`** (not an AS→
download-capable mapping); the `active` flag gives the automated/
manual split for free (`run_all` filters active_only, so active=1
CSV/API AS rows are the automated sweep, auth-gated/XLSX active=0 go
manual). **Capability csv → widen the existing per-source matrix
rows** with the 6 capability columns + derived predicate flag (one
csv artifact; the N2 numerator stays md+json only).

## Capability profile (the core new concept)

The profile answers, per source, six questions against the product
model. All six are probe_metrics recorded per source (a capability run
or a manual capability record); v_probe_latest gives the current
profile per source × metric.

| Metric | type | meaning | value vocabulary |
|---|---|---|---|
| `products_identifiable` | numeric | volume — how many products the source features | count |
| `cap_manufacturer` | numeric | exposes a manufacturer/org field | 0/1 |
| `cap_product_ident` | numeric | exposes a product-ident field (licence no / UFI / article code / SKU / GTIN) | 0/1 |
| `cap_cn8_linkage` | text | mechanism to reach the 13 CN8 codes | `category` / `prodcom` / `eupcs_proxy` / `manual` / `none` |
| `cap_depth_tier` | numeric | data depth | 1 name-only · 2 name/ident + some technical · 3 deep technical + manufacturer-internal docs · 4 standardized specs + IATA/CMR MSDS |
| `cn8_reachable` | numeric | how many of the 13 CN8 codes reachable | 0–13 |

The 0/1 flags avoid brittle string-matching (the C2 lesson, nu8): the
predicate tests flags, the *mechanism* is the descriptive text metric.

### The "real product source" predicate (report-time)

A source passes the "is a product URL a product" test when:

    cap_manufacturer = 1
    AND cap_product_ident = 1
    AND cap_cn8_linkage != 'none'
    AND cap_depth_tier >= 2

This is derived in the report assembly, never stored — the filter and
its rationale are analytic prose (nu5/method-sheet precedent); the
underlying counts are DB-cited.

## Register-capability machinery (cap1/cap2/cap4)

- **probe_mode `capability`** (0007 INSERT) — drives a
  register-capability adapter branch. CLI already takes `--mode`
  (choice list gains the value); `probe record --mode capability`
  labels manual capability records (mode parameter exists, e8).
- **Register-capability branch** for `access_method_code IN (download,
  api)` official-register sources (EU Ecolabel ECAT CSV, Nordic Swan
  CSV, PRODCOM/stat APIs): fetch the export → inspect the header/shape
  (does it expose manufacturer / product-ident / a nomenclature column?)
  → count rows → emit capability findings + `products_identifiable`.
  Legitimate reconnaissance (D3 — official exports over scraping).
- **AS adapter mapping:** AS is the class of the official product-level
  registers and association member lists; it currently has **no
  adapter** (dispatch is CS/PE/ST). The register-capability branch is
  exposed under AS (a new ASAdapter or an AS→download-capable mapping,
  decided at implementation); it dispatches on `access_method_code`.
  Sources exposing a data export (CSV/API) ship `active=1` and ride the
  automated branch; auth-gated or XLSX-only sources ship `active=0`
  (manual-web default, nu3) and are characterized by manual record.
- **XLSX/auth-gated (Blue Angel XLSX, INIES API) and PE universe:** no
  automated parse — download + human review, recorded via
  `probe record --mode capability` (cap2). PE-universe *volume* per
  channel uses existing `sitemap_products` recon where available and
  manual `products_identifiable` records for the enumeration counts.
- **PE universe enumerated, not scraped** (U4): CEPE member sites, DIY
  chains, marine, art — added as per-site PE rows with an inclusion cap
  and a volume characterization; no catalog scraping.

## CN8 linkage (deferred codes)

v0.2.1 records the **linkage mechanism per source** (`cap_cn8_linkage`)
and the reachable count (`cn8_reachable`). The 13 CN8 codes and the
PRODCOM↔CN8 / EuPCS↔CN8 mapping tables stay deferred to 0008/M1 (`cn_code`
ships there) — no per-code rows in this unit. Open-item carry: retrieve
the official Eurostat PRODCOM↔CN8 correspondence document; treat EuPCS
PC-PNT-2 as an approximate proxy for CN 3208/3209 with explicit
caveats; verify the 13 codes against the current CN year (EUR-Lex Reg.
2658/87 as amended).

## Report extension (cap3)

Extensions to the od8 content layer (one DB-only assembly, three
renderers — i12 unchanged):

1. **Capability matrix section:** per registered source — the six
   capability metrics + the derived real-product-source flag. md
   explains the predicate in prose; csv/json carry the six columns.
2. **Preliminary N2 numerator line:** Σ `products_identifiable` over
   sources passing the predicate — a floor, with the honest caveat that
   official registers are certified/declared subsets, never a market
   total (labels as "N2 numerator (official registers, floor)").
3. csv = matrix; json = full structure incl. the derived predicate and
   the N2-numerator components.
