# Unit v0.1.1 — Design delta: source probing (slim CLI)

## Abstract

The Design for the first build unit: the probe-era slice of `leadhs`.
Strategy fixed what and why (10_STRATEGY/v0.1.1.md); this file fixes
the technical how for exactly this unit — which tables are migrated,
which commands exist with which semantics, how each source class is
probed, and the order the code is written in. Everything else in the
Design MASTER docs is design-ahead for later milestones and is not
built here.

## What Design adds beyond the Strategy unit scope

All addenda stay inside the "probing tools + db" envelope; each is a

## CLI implemented

`db init|status|audit`, `source load|list`, `probe run|record`,
`probe report`, `doctor` — full contracts in interfaces.md. Exit
codes 0/1/2/3; `--verbose`; `--db PATH`; contact via `LEADHS_CONTACT`.

## Probe workflows per source class

- **CS-1 swiss-impex** — format_check + census: small test export
  (3208, one year, one partner) → format, granularity,
  coverage_years, export_rows, free_access; export archived as a
  document. Closes the Strategy's high-priority open item.
- **CS-2 Comext** — light re-check only (already verified).
- **PE-1..4** — census: robots/terms/rate_limit/languages; category
  enumeration + counts; sample N=5 products → page_sample_ok,
  sds_sample_ok; sample pages raw-archived. The PE candidate-site
  seed list enters the register CSV as it is discovered (register of
  record).
- **ST-2 SPIN** — format_check: download availability, mdbtools
  presence, small extraction attempt → extraction_path; DB file
  hashed + archived.
- **ST-1 PCN** — access_check via `probe record` (manual-web
  findings, method=manual).
- **LG** — not probed (manual legal workstream, Strategy).

## Anchor promotion (procedure — executed at M1, fixed here)

1. `probe report` lists candidates (v_anchor_candidates).
2. A human method decision inserts a population_anchor row with
   `promoted_from_finding_id`, anchor_code, value/unit, year,
   provenance note (catalog coverage bias is judged here — never
   automatic; 10_STRATEGY/MASTER.md D20).
3. `frame promote` (M1 command) wraps step 2; in the gap, SQL insert
   per data_model.md.

## Implementation phases (design-level; 30_IMPLEMENTATION formalizes)

- **P1 scaffold** — pyproject, package skeleton, metrics constants,
  typed errors, ids.py.
- **P2 persistence** — store.py, db.py (migrations 0001/0002, status,
  audit), models.py.
- **P3 network & env** — fetch.py (robots/rate/retry/dry-run),
  doctor.py.
- **P4 register** — sources.csv authored from the DATA_SOURCE.md
  register (13 rows), source load/list.
- **P5 probe** — engine.py + CS/PE/ST adapters + probe record.
- **P6 reporting** — report.py (md/csv/json) + view tests.
- **P7 tests** — full matrix (testing.md), CLI smoke, chaos, hostile.
- **P8 census run** — the unit's operational goal: run the real
  census against the register and deliver `probe report` (post-build
  execution, not code).

## Acceptance criteria

- Migrations apply clean on a fresh DB; re-init idempotent; backup
  taken on upgrade.
- `db audit` exit 0 on the fixture corpus; violations detected in
  negative tests.
- Full test suite green offline (net/mdbtools markers deselected).
- `probe run --dry-run` performs zero network calls (test-enforced).
- `probe report` renders md/csv/json from views.
- Census executed against the real register: every OPEN register row
  probed or explicitly manual (PCN), findings recorded, blocked
  sources documented (the Strategy unit deliverable).

## DECISIONS (unit-level design)

- ud1: per-source runs + abort semantics (architecture a2).
- ud2: probe record included (PCN manual-web needs a provenance-clean
  entry path).
- ud3: doctor included (first-run de-risking on Slackware).
- ud4: report formats md/csv/json (census feeds manual frame work).
- ud5: dry-run opt-in flag, default off; sample default N=5.
- ud6: backup-before-migration default on.
- ud7: metric extension via migration only (no runtime inserts).
- ud8: register of record = repo CSV; `source add` deferred.
