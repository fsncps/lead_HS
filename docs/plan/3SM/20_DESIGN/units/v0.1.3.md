# Unit v0.1.3 — Design delta: data-landscape map (enumeration, priors, aggregate report)

## Abstract

The Design for unit v0.1.3 — the data-landscape mapping unit
(strategy `10_STRATEGY/v0.1.3.md`, refocused 2026-09-12 per D29).
The unit turns the census floors into the map the study decides on:
per-source availability profile (scale x, spec access y,
constraints), the two numbers as measured floors, coarse register
priors, latest-year trade context, and a frame-decision bridge. This
file fixes the technical how: the enumeration register model
(per-site PE rows, load validation), the priors metric (migration
0005), and the landscape-map extensions to the od8 report content
layer (aggregate sections, bridge). No new pipeline stages, no new
CLI commands; the only migrations are metric INSERTs. The unit also
**absorbs the outstanding v0.1.2 D28 rework and census execution**
(PHASE01–02 here; same precedent as v0.1.2 absorbing v0.1.1's
PHASE08, B8/D26): the built code still predates the D28 rework (no
migration 0004, no `products_listed`/`doc_links_seen`, register
still 14 rows incl. inactive LG/LI), and PHASE07 of v0.1.2 awaits
execution.

## CEO review (2026-09-12, mode HOLD SCOPE)

Review applied per the HOLD-SCOPE mandate; the findings ARE the
decisions below. Highlights: enumerated sites enter the register as
**their own source rows** (per-site provenance, per-site run_keys,
per-site floors; aggregate buckets would make floors unauditable);

load` gains **validation** (id pattern, URL scheme, duplicate-host

(a budget-exhausted walk is flagged via a numeric metric; floors
are lower bounds and

only; blocked/failed/not-yet-walked sources excluded from the sum
AND counted in the aggregate line; zero completed walks → an
explicit "no measured floors yet" line, never a bare 0); census
execution over the enumerated register stays **phased** (verify on
two sites, then full — GO=1 each step).

## Enumeration register model (pe1)

- **Per-site rows:** every enumerated site becomes one `source` row
  (`PE-10`, `PE-11`, … — numbering continues past the retired
  1–4). Each row carries the site's real URL, `class_code=PE`,
  `access_method_code=scrape`, and the structured notes convention:
  
      channel=<CH-DIY|EU-DIY|MARINE|ART|B2B|MFR>;
      listed_by=<who listed it, e.g. "ECHA biocides list", "manual">;
      listed_url=<where it was listed>;
      listed_date=<YYYY-MM-DD>;
      inclusion=<why it qualifies, one clause>
  
  The convention is defined authoritatively in interfaces.md (i13)
  and parsed only by humans and the report's channel-facet grouping
  (stringly until M1 — accepted by review).
- **PE-1..4 retirement:** after the enumerated rows load, PE-1..4
  flip to `active=0` with a `census_status` note "superseded by
  per-site enumeration (see PE-10..)" — reference rows are
  updatable, never deleted (P6); their findings/history stay. Their
  seed URLs live on as per-site rows (e.g. epifanes.com → PE-10).
- **Load validation (source load):** new row-level checks, exit 1
  with the offending row named: id matches `^[A-Z]{2}-[0-9]+$`;
  url non-empty and http(s); **duplicate host among active rows**
  (netloc lowercased, `www.` stripped) rejected — one site must not
  be double-counted into the floor; inactive rows are exempt
  (historical rows may share hosts, e.g. the retired echa.europa.eu
  pair). Cross-listing of the *same product* on different sites
  stays the qualitative W4 overlap caveat — the check is per-site,
  not per-product.
- **Growth discipline (W6):** enumeration lands as one reviewed CSV
  change set per channel batch (cap per channel documented in the
  CSV batch note); no ad-hoc additions mid-walk.
- **3213 annex:** art-channel rows (channel=ART) carry the
  artists'-colours categories in their walk scope — same mechanics,
  no separate design (D13).

## Landscape-map report extensions (pe3)

Extensions to the od8 content layer (single DB-only assembly, three
renderers — i12 unchanged):

- **Aggregate floors section (md, after the summary matrix):**
- Q1 line: Σ `products_listed` over **active** PE sources whose
  latest census run is `done` — "observed floor: N products across
  M of K walked sites (B blocked, F failed, U not yet walked)" —
  citing the constituent run_keys (grouped list; R4/P7 respected).
  Budget-limited sources are flagged inline ("≥, walk
  budget-limited") via the `walk_budget_exhausted` metric; retired
  inactive rows (PE-1..4) never enter the sum (decision 1A).
  - Channel-facet subtotals (parsed from the notes convention:
    CH-DIY, EU-DIY, MARINE, ART, B2B, MFR) + the W4 overlap caveat
    sentence (cross-listing not deduplicated).
  - Q2 line: Σ `doc_links_seen` (same inclusion rule) + the
    `sds_sample_ok` context.
  - Zero completed walks → "no measured floors yet — census not
    executed or no walk completed" (never a bare 0).
- **Trade context lines:** one compact line per CS source from
  `records_hs3208/3209/3213` (D28 grain rule; absent = "—").
- **Priors lines:** one line per ST source from
  `products_registered` / `census_status`.
- **Frame-decision bridge (md only):** qualitative, evidence-cited:
  channel coverage (how many channels have completed walks), floor
  magnitude vs the 10⁴–10⁵ hypothesis, SDS access rates
  (doc_links_seen/products_listed), blocked share. No invented
  numeric gate. With no floors yet it renders the explicit deferred
  line.
- **csv:** the summary matrix gains columns `products_listed`,
  `doc_links_seen`, `products_registered`, `walk_note`
  (budget/blocked marker); json carries the full structure
  (aggregate dicts incl. excluded-source lists).
- Everything cites run_keys / manual records (W7); framing stays
  product-data-only (D27).

## Walk budget marker (pe4)

A walk that exhausts its page budget (D28 mechanics: BFS depth ≤ 3,
budget ≤ 12 incl. homepage) emits the numeric metric
**`walk_budget_exhausted`** (0/1, third INSERT of migration 0004 —
ENG review decision 2A). The report's per-source line and the
aggregate flag such floors as budget-limited ("≥ observed,
budget-limited") by reading the metric like any other — no note
substring parsing (the od9 R4 notes-seam lesson applied). Documented
in interfaces.md (i13); no schema change beyond the INSERT.

## Aggregate inclusion rule (ENG review decision 1A)

Aggregate floors sum **active** sources only whose latest census run
is `done`. Retired rows (PE-1..4, inactive after enumeration) keep
their done landing-page runs and stay visible in the matrix — but
never enter the sums; otherwise the stale landing-page floors would
double-count on top of their per-site successors (PE-10+). The
excluded-and-counted line covers blocked/failed/not-yet-walked
*active* sources; inactive rows are named once in a footnote.

## Acceptance criteria

- `source load` rejects malformed rows (id/url/dup-active-host) with
  the row named, exit 1; the pre-slim 14-row register still loads
  (`--file`; LG/LI inactive exemption).
- Migration 0004 applies (backup taken): LG/LI rows gone,
  products_listed/doc_links_seen in the vocabulary and
  v_anchor_candidates; sync test green.
- Census executed (PHASE02): every row probed or explicitly manual;
  report published; `db audit` exit 0.
- Enumerated register loads; `probe-dry` plans every active per-site
  row; PE-1..4 inactive with supersession notes.
- Migration 0005 applies; `products_registered` recordable via
  `make record`; v_anchor_candidates includes it.
- Map (md) shows: aggregate Q1/Q2 floors with done-only sums,
  excluded/blocked counts, budget-limited flags, channel subtotals +
  overlap caveat, trade-context lines, priors lines, bridge (or its
  deferred line); csv matrix carries the new columns; json the full
  structure; every number cites run_key/record.
- Full offline suite green incl. t9; goldens regenerated with
  review; wheel still builds (version bump only if phases change
