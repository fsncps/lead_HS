# Unit v0.2.3 — Design delta: pool-estimate meta-benchmarking (the magnitude-class verdict)

## Abstract

The Design for unit v0.2.3 (strategy `10_STRATEGY/v0.2.3.md`, D35,
as reframed by the design turn 2026-09-14). The v0.2.2 funnel
delivered Q1 = [85,840–343,360] (modeled), Q2 = 17,170 (counted
floor), Q3 = 3,590 (modeled reach). User direction: the Q1 range is
too wide and its basis opaque; the study should be able to say with
reasonable-high confidence which **magnitude class** the total number
of individual paint products/formulas falls into:

> a) 20k–50k · b) 50k–100k · c) 100k–200k · d) 200k–300k · e) >300k

(Classes made contiguous at the design turn so every possible total
maps to exactly one class.) The unit's center of gravity is
**meta-benchmarking** — triangulating the total market volume against
independent external quantities — not reconciliation of our own
numbers. The v0.2.2 refinement analyses (ECAT category structure, PE
assortment distribution) are kept as **supporting evidence**. The
deliverable is a **class verdict, dual-level**: one class at the
registration/SKU level and one at the formulation level (the D2
collapse, plausibly 3–10×), each with the pinned confidence rule.

Development stays minimal: one staging adapter (Danish AT open
dataset), one report section, analysis queries — **no migration, no
new CLI commands, no new Make targets** (V9).

## CEO review (2026-09-14, mode HOLD SCOPE)

Findings c1–c7, all folded into this design (no open decisions):

- **c1 — indeterminate benchmarks are visible:** a benchmark that
  cannot be computed (no penetration denominator; BfR ambiguity
  unresolvable) renders as an explicit `indeterminate` row in the
  vote table — never dropped silently; the confidence rule counts
  *available* benchmarks, and **fewer than three available ⇒ the
  verdict reads "insufficient basis"** (a legitimate, visible
  outcome).
- **c2 — compression factor is a range per key tier:** the EAN is
  16% missing, licences group products; the SKU↔formulation factor
  is computed per key hierarchy (EAN → name-dedup → licence) and
  reported as a range, never a point.
- **c3 — tie rule:** a vote landing on adjacent classes reports the
  span plus the assumptions that would flip it; **confidence is not
  claimed on a tie**.
- **c4 — vintage discipline:** every vote-table input carries its
  reference period / retrieval date (09/2026 staged ECAT vs 03/2026
  Commission facts must not mix silently); cross-vintage deltas
  above a stated threshold are flagged on the affected row.
- **c5 — never scale from zero:** if the Danish data yields zero
  paint rows (counted-0 semantics, v0.2.2 c2), B2 is marked
  indeterminate — no scaling from an empty base.
- **c6 — sparse categories:** a sparse function-category column in
  the Danish data widens the B2 range with an explicit missingness
  note.
- **c7 — the vote generator is a pure function** over a
  benchmark-result structure (name, quantity, vintage, band, class
  implication), with a report golden test — no report-time state.

## Core concept: six benchmarks, one vote

| # | Benchmark quantity | Implies a class via | Inputs |
|---|---|---|---|
| **B1** | EU tonnage 3.7–4.2 Mt/yr (JRC AHWG) ÷ per-SKU throughput scenarios | volume-Fermi | extraction: per-product turnover figures (abstracts) |
| **B2** | National register paint counts (DK staged; SE via BfR PDF; NO dated) × EU scaling with scope corrections | per-capita / per-market scaling | X3 rows; X4 extractions |
| **B3** | PCN 1.4M mixtures × paint share + non-hazardous uplift | mixture-register benchmark | SWD(2022) 435 Annex 16; national breakdowns |
| **B4** | Bottom-up: producer counts × assortment distribution | structural build-up | X2 PE distribution (staged); producer counts |
| **B5** | ECAT-inverse: reconciled certified count ÷ penetration scenarios, incl. the **empirical penetration probe** ECAT∩DK over DK paints | label-penetration inversion | X1 refinement; X3 overlap |
| **B6** | External literature: other-market product counts, cross-industry SKU benchmarks, retail-depth scaling | out-of-pool sanity anchors | bounded extraction attempts; documented-gap outcome acceptable |

Each benchmark computes **low/base/high scenarios** with explicit
assumptions; each scenario implicates one or more classes.

```
 benchmark input ──▶ arithmetic ──▶ class vote ──▶ verdict
      │                │               │             │
   [missing doc?]   [zero input?]  [no overlap?]  [<3 available?]
   [vintage mix?]   [sparse col?]  [adjacent tie?]→ "insufficient
   [schema drift?]  [indeterminate]→ row stays      basis" — visible,
   → blocked/                        visible         never guessed
     format-finding
```

**Vote table:** rows = benchmarks (with vintage + assumption notes),
columns = classes a–e; each cell marks the class(es) the benchmark's
base scenario implicates, with low/high arrows. **Verdict rule
(pinned):** the class implicated by the most independent available
benchmarks at base; *reasonable-high confidence* = ≥3 available
benchmarks implicate the same class AND no benchmark is exclusively
compatible with a non-adjacent class; a tie renders the span + flip
assumptions without a confidence claim (c3); each benchmark
incompatible with the verdict becomes an explicit open item —
divergences are findings, not noise.

**Dual-level verdict:** B2/B3 measure registration-level products;
B4/B5 can be run at both levels; the compression factor (c2)
connects them. The report states the class per level.

## Testing additions (t13)

- **Refinement:** category-breakdown and key-tier queries pinned on
  synthetic distributions (hostile-QA: distributions chosen to flip
  the compression factor — the report must show the flip honestly).
- **Danish adapter:** fixture built in-test (real shape);
  aggregates-only fallback path; idempotent re-run; interrupt →
  no orphan rows (existing per-source transaction, re-tested).
- **Benchmarks:** scenario-propagation arithmetic; vote-table
  generation as a pure function; confidence-rule unit tests —
  convergence counting, exclusive-conflict detection, tie → span,
  <3 available → "insufficient basis" (c1/c3 paths); zero-paint
  input → indeterminate B2 (c5).
- **Report:** golden test for the vote-table rendering (c7);
  supersession rendering (v1 marked superseded, v2 headline);
  indeterminate rows never silently dropped.
- **Vintage:** cross-vintage delta flag rendering (c4).
- Suite stays fully offline; no flakiness sources introduced.
