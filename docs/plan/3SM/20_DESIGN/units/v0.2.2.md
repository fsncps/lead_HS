# Unit v0.2.2 — Design delta: the three-question funnel (product-identity and granularity sounding-out)

## Abstract

The Design for unit v0.2.2 (strategy `10_STRATEGY/v0.2.2.md`, D34).
v0.2.1 built the capability machinery and measured it on ~1 of ~10
capability sources, with the headline number (17,838, ECAT) existing
only as hand-typed manual records. v0.2.2 **improves on v0.2.1's goals
and methodology** without pulling v0.3 forward: it measures the data
landscape as a three-question funnel under the study's product model
(**Product = manufacturer + manufacturer-internal ident number**) —
Q1 pool per CN8 (modeled), Q2 definitively identifiable (counted
floor), Q3 SDS reachable (modeled reach) — at the granularity
achievable without pulling large datasets or scraping. Two enablers
(user direction 2026-09-14): a **runtime budget** (30–60 min runs,
default 60 min) and a **test-data staging DB** allowed for test runs
(no product-DB seeding, D31 recon-only holds).

Two design principles, drawn directly from the v0.2.1 review:

1. **Completeness is a testable invariant, not operator discipline.**
   The v0.2.1 exit gate ("every source recorded or documented-blocked")
   was marked done while unmet; PHASE03 scope was silently cut. Here,
   every register row ends the run with a machine-checked disposition.
2. **Every number is a query result, never a typed literal.** The
   v0.2.1 numerator was unreproducible from any DB state. Here, counts
   derive from staged rows by construction.

The design principle for structure: three measurement **layers** with
reconciliation between them (below), riding the existing probe
machinery — no new pipeline stage, no new CLI command (V9); new
options on `probe run` and one new Make target.

## ENG review (2026-09-14, mode BIG CHANGE)

Findings e1–e8, folded into this design and the implementation plans:

- **e1 (ingest path):** staged rows flow **in `ProbeResult`**;
  adapters return parsed rows, the engine writes **staging first,
  then evidence**, per source; recovery from the two-store gap (SQLite
  cannot transaction across files) is a plain idempotent re-run —
  never silent drift. Explicit > clever; testable end-to-end.
- **e2 (run_all filter):** the hardcoded capability-mode AS-filter
  generalizes to an optional source-selection parameter; waves pass
  filters from the CLI layer. No `mode ==` chain growth (DRY).
- **e3 (module placement):** new modules `leadhs/xlsx.py` (stdlib
  XLSX reader), `leadhs/normalize.py` (identity normalization), 
  `leadhs/staging.py` (schema/loader) — adapters.py (1,122 lines)
  absorbs none of them; one shared CSV-shape helper (encoding/BOM +
  header validation) and one `_sniff` gate (content-type + first
  bytes) used by every export consumer; `_depth_tier` moves to the
  shared helpers so adapter and report agree on one definition.
- **e4 (normalized at ingest):** normalized manufacturer/ident stored
  as staging columns; overlap/union = SQL over staging — no
  report-time Python matching layer; ident/manufacturer columns are
  **TEXT with explicit cast** (SQLite type affinity: leading zeros
  survive), tested byte-identical.
- **e5 (report's second store):** report assembly takes an optional
  staging path; staging sections render conditionally with an
  explicit "staging absent" note — evidence-only runs still report.
- **e6 (Comext batching pinned):** per-CN8 × flow queries (~39
  payloads), per-query timeout + retry, batch shape fixed in this
  doc; PRODCOM bulk TSV sidesteps the API size limit.
- **e7 (test plan):** six specs added beyond the plan's list —
  BOM/encoding, column drift, leading-zero round-trip, counted-0,

- **e8 (bookkeeping):** TODOS.md — jsonstat entry retired, two new

  data_model.md design-ahead renumber in the same change set.

## Core concept: three measurement layers

| Layer | Store | Holds | v0.2.1 failure it fixes |
|---|---|---|---|
| **L1 — source facts** | evidence DB (probe_metrics + register) | what a source *is*: the six capability metrics + `sds_doc_urls`; register rows with `export_url`/`export_format` | landing-page-only rows; provenance in free-text notes |
| **L2 — staged observations** | `data/testdata.sqlite` (NEW) | what a source *delivered*: product rows, trade rows — each with `source_id + document hash + retrieval date + run_key`, fed **only from archived documents** | the hand-typed 17,838 (`notes: null`) |
| **L3 — derived analyses** | report-time | identity counts, deduped union + overlap, CN8 trade table, pool model v0, census | numbers assembled by query, not literal |

**Reconciliation contract:** for staged sources, `products_identifiable`
and friends are **derived at run close from the staging rows** (metrics
== staging by construction); manual sources emit directly as today
(`record_manual`). Tests pin report numbers == staging queries. The
staging DB is rebuildable from the document archive alone (c3).

## The four-wave run

Waves are (mode, source filter, budget) presets over the existing
run machinery — no new pipeline stage. Global default 60 min
(`--budget` override), resumable per-source on existing run semantics.

| Wave | Content | Mode | Budget | Exit gate (per-source disposition) |
|---|---|---|---|---|
| **W1 — bulk official exports** | ECAT CSV full ingest (88,920 rows → group 044); Nordic Swan export (mechanics pinned first); Blue Angel XLSX via `xlsx.py`; PRODCOM bulk TSV; Comext per-CN8 × flow × declarant | capability | ~20 min | `counted` (staged rows) or `blocked`+recorded |
| **W2 — register completion** | IBU/environdec real export inspection; INIES auth status (manual-record this unit); new rows NF Environnement, natureplus, EPD Norway, KEMI; **manual-fallback step built into the wave definition** | capability | ~10 min | every row dispositioned |
| **W3 — PE universe** | full enumeration (CEPE ~800 → rows, `active=0`); widened robots-compliant recon: sitemap product counts + **SDS-document-URL counts** (new metric) | recon | ~20 min | enumerated + recon dispositions |
| **W4 — manual records & LI** | VdL/FIPEC/BCF member counts; IPEN/UNEP/EEA/ILZSG; stragglers | manual record | ~10 min | recorded or document-blocked |

**After-run invariant (test-backed):** after a wave completes, no
register row remains `pending` or `format-finding` — every row carries
a terminal disposition.

```
 register row ──▶ pending ──▶ counted (incl. counted-0, c2)
                          ├─▶ manual-recorded
                          ├─▶ blocked
                          └─▶ format-finding ──▶ manual fallback ──▶ terminal
```

Staging-ingest data flow (the one new flow, all four paths):

```
archived doc(hash) ─▶ parse ─▶ normalize ─▶ stage rows ─▶ run-close metrics
      │                │           │             │                │
  missing?         HTML-as-CSV  mfr unparseable  dup(src,run)?  count==rows?
  → loud error     → _sniff →   → preserved raw  → replace per  → reconciliation
  (no staging row    format-      + ident_basis    (source_id,    true by
   without doc       finding                       run_key)       construction
   hash)
```

## Granularity ladder (what the landscape data reports at)

- **G1** per-source — capability profile complete, 100% dispositions.
- **G2** per-register aggregates — entries / distinct manufacturers /
  distinct (mfr, ident) pairs / identity completeness % / category
  distribution (staging SQL).
- **G3** per-CN8 — trade table: imports kg/€, exports, intra-EU
  (flow codes verified or caveated), production approx via
  PRODCOM↔CN8, observed-products floor.
- **G4** per-member-state — declarant dimension (cheap
  re-aggregation); production per MS where cheap.
- **G5** cross-register — deduped union + pairwise overlap
  (ECAT ∩ Nordic Swan pilot), containment + Jaccard reported,
  labeled calibration-only.
- **G6** per-PE-site — product URLs, SDS doc URLs, channel, country.
- **G7** census — class × channel × country; enumerated vs probed
  vs counted.

  archives every fetch); staging product rows are the v0.3
  seed-schema rehearsal.

## Identity & matching (the dedup design)

- **Normalization** (`leadhs/normalize.py`, shared by ingest and
  overlap): manufacturer — casefold, diacritic fold, legal-form
  suffix strip (GmbH, AB, Oy, Ltd, S.A., A/S, …), punctuation
  collapse; ident — strip spaces/dashes.
- **Identity triple:** (manufacturer, manufacturer-internal ident,
  CN8-as-metric). ECAT and Nordic Swan entries both carry licence
  numbers → `ident_basis=ident`; name fallback flagged
  `ident_basis=name` (aggressiveness: exact normalized-name match
  only within the same register-pair pilot — no fuzzy matching in
  v0.2.2; the rule and its validation are pinned here, c5).
- **Overlap pilot:** ECAT ∩ Nordic Swan on normalized
  manufacturer + ident; containment |A∩B|/|A| (smaller register) and
  Jaccard both reported, labeled calibration-only.
- **Union numerator:** distinct (manufacturer_norm, ident_norm)
  pairs over staged registers → "definitively identifiable: N
  (floor)" — the Q2 answer.

## Depth ladder (refined wording — dissolves the ECAT tier-2 wrinkle)

1. name only · 2. name + ident/licence + category (registry
metadata, no technical data) · 3. adds technical performance data /
downloadable tech docs (SDS/TDS links) · 4. standardized full
documents (EPD declarations; IATA/CMR MSDS). ECAT = tier 2 ✓
(name, licence, company, category — no technical data).

## Pool model v0 (the Q1 model form)

`P(cn8) = M × s(cn8)` — producer count (CEPE ~800 primary; SBS
NACE 20.30 = 3,200 as the wider bound) × products-per-producer
distribution (staged register licence-holders + W3 recon sitemap
counts) × CN8 volume share `s` (Comext kg + PRODCOM value).
Reported as a **range** [P_low, P_high] with a method sheet;
"modeled estimate" labels throughout. Pure arithmetic at report
time — no model framework.

## Report extension

Probe-report extensions (od8: one DB-only assembly, three renderers —
i12 unchanged): **funnel summary at top** (Q1 range / Q2 floor / Q3
reach, epistemic labels, the v0.5 ratio formula Q2÷Q1) + **CN8 trade
table** + **identity table** (per register + union + overlap) +
**complete depth matrix** (every source; counts per tier) + **SDS-URL
counts** + **pool model v0** + **source census** (enumerated vs
probed vs counted). Staging sections render conditionally with an
explicit "staging absent" note (e5); any reconciliation failure
renders as a visible flag on the affected number, never silence (c4).
csv/json carry the full structure.

## Testing additions (t12)

- **Fixture corpus:** synthetic ECAT/Nordic CSVs (semicolon dialect,
  BOM variant), XLSX fixture **built in-test via stdlib zipfile** (no
  binary blob, no openpyxl), Comext per-CN8 JSON-stat fixtures,
  PRODCOM TSV fixture.
- **Reconciliation:** metric == staging count (by construction,
  tested); report numbers == staging queries — the 2am-Friday test.
- **Hardening:** `_sniff` regression (HTML-as-CSV, the AS-7 class);
  malformed export; 403 blocked; dry-run plans zero fetches.
- **Staging:** idempotent re-run (counts stable); hash-mismatch on
  archived docs detected; missing doc hash → loud ingest failure;
  leading-zero ident round-trip; rebuild-from-archive.
- **Waves:** budget expiry mid-wave (virtual clock) → resumable,
  no partial source; after-run disposition invariant; wave filter
  selection.
- **Matching:** normalization variant grid (legal forms, umlauts,
  punctuation); overlap math on fixtures.
- **Migration/sync:** 0008 applies; sync 0001–0008 == metrics.py.
- **Make:** `landscape` target guarded (GO=1), WAVES/BUDGET
  pass-through.
- **Chaos:** interrupt mid-ingest → no orphan staging rows
  (per-source transaction); interrupt mid-wave → completed sources
  persist.

## DECISIONS (unit-level design)

- **fu1:** three-layer measurement architecture; reconciliation by
  construction (run-close derivation) + tests.
- **fu2:** staging DB `data/testdata.sqlite`, fed only from archived
  documents; idempotent replace per (source_id, run_key); rebuildable
  from archive; per-source transaction — staging first, then
  evidence.
- **fu3:** migration 0008 — `sources.export_url`/`export_format` +
  metric `sds_doc_urls`; design-ahead renumber 0009–0015; no new
  probe_mode (waves compose capability/recon); no new CLI commands
  (new options only).
- **fu4:** identity counts are staging SQL aggregates over normalized
  columns; minimal metric set (fu-metrics).
- **fu5:** wave harness at the CLI/Make layer — no engine budget
  concept; generalized run filter (e2); disposition invariant
  test-backed (c1); counted-0 semantics (c2).
- **fu6:** W3 recon ~75 active sites (MFR≤40/DIY≤10/MARINE≤10/
  ART≤15); SDS-doc-URL counts; full PE universe enumerated,
  not probed.
- **fu7:** normalization shared module; exact-match-only overlap
  pilot with ident_basis flag; containment + Jaccard, calibration-only.
- **fu8:** depth-ladder wording refined (tier 2 = registry metadata
  without technical data).
- **fu9:** pool model v0 = arithmetic + method sheet; report =
  probe-report extensions (od8 unchanged).
- **fu10:** jsonstat module lands here (multi-dimension decode for
  per-CN8 × declarant Comext queries); TODOS entry retired in build.
