# Unit v0.2.4 — Design delta: management CSV sample (`leadhs probe download-csv-sample`)

## Abstract

Design for unit v0.2.4 (strategy `10_STRATEGY/v0.2.4.md`, D36). One
new probe command draws, per registry, 100 random in-scope product
items with all available data fields as CSV for management review,
plus a generated manifest answering three questions per registry:
what fields are returned per product item, whether
cross-identification is possible, which identifier columns exist.
Development is one module + one Make target + tests; no schema change
— the only migration is 0009, a lookup-seed INSERT (probe_mode
`csv_sample` + the two probe_metric codes; the i4 vocabulary
extension path 0003/0005/0006/0007 use), pinned by the t6 sync test.

## Per-registry behavior

| Source | Behavior |
|---|---|
| AS-2 ECAT | One bulk GET of the pinned export_url → raw-store archive → shared CSV parse (`read_csv_rows`) → in-scope group filter (reuse `_in_scope_group`) → `random.Random(seed).sample(n)` → CSV (all export columns verbatim + provenance columns) |
| AS-3 Nordic Swan | Bounded export discovery (≤5 polite rate-limited GETs on the known search surface; CSV/Excel endpoint patterns). Success → ECAT path with criterion-096 filter. Failure → honest manifest record ("export mechanics unpinned — browser pass required") |
| ST-1 PCN | No fetch. Manifest record: PCN database authority-only (appointed bodies; poisoncentres.echa.europa.eu, accessed 2026-09-14) |
| ST-7 SE | No fetch. Manifest record: KemI Products Register secrecy-protected at product level; public = aggregates (KemI-stat) |
| ST-6 DK | No fetch. Manifest record: aggregates-only via embedded Power BI (v0.2.3 PHASE02 shape gate) |
| ST-3 SBS | No fetch. Manifest record: enterprise statistics (NACE C2030) — no product items |

**Per-source state machine** (review Issue 1 → decision 1A: the
manifest is ALWAYS written and tells the truth per source; the exit
code flags the failure):

    pending ──▶ delivered    (csv_sample_rows; exit contribution 0)
         ────▶ unavailable  (csv_sample_unavailable, expected → exit 0)
         ────▶ failed       (should-deliver only → exit 2)

## Exit codes

- 0 — every source ended delivered or expected-unavailable.
- 2 — a should-deliver source failed (fetch error, column drift, 0
  in-scope rows after the filter). Consistent with the probe
  convention (i1); the census/recon/capability chains already
  tolerate exactly exit 2.
- Usage errors (`--n < 1`, unknown `--source`, uninitialized DB) —
  exit 1 per the i1 mapping (`main()` hardcodes UsageError → 1);
  never 2.

## Review outcomes (2026-09-14 — CEO + ENG review, HOLD SCOPE)

Both reviews ran HOLD SCOPE (scope unchanged, S1–S4 in force).
Findings folded here:

- **1A (manifest semantics):** manifest always written with
  per-source delivered/unavailable/failed; exit 2 flags failure —
  zero silent failures (the report card exists and tells the truth).
- **Amendments:** in-scope pool < n → clamp + manifest shortfall
  note (stdlib `random.sample` would raise); draw from DISTINCT
  product items (product+company+group triple), pool size pre/post
  dedupe reported; `--n ≥ 1` and `--source` validated (exit 1);
  tests use an injected clock/ts (no flaky timestamps); AS-3
  discovery catches the named taxonomy only (no bare except); 0
  in-scope rows after the filter = failed (data-drift signal), not
  a silent empty CSV.
- **Migration correction:** strategy "no schema migration" refined —
  lookup-seed migration 0009 (probe_mode + 2 metric codes), no new
  tables; t6 sync updated to 41.
- **Error/rescue map:** 6 failure paths mapped (fetch, parse,
  clamp, CLI args, CSV write, AS-3 discovery) — 0 critical gaps
  after the amendments; failures land as run status + text finding,
  never silent.
- **Security:** no new deps/secrets; public GETs via the polite
  Fetcher; Low/Low Excel-formula note (CSVs are data) — no action.
- **Performance:** one GET, ~18k-row parse (<10 MB); p99 = network.
- **Rollback:** git revert; no migration/backfill; GO=1 gate.
- **Reversibility 5/5** (additive module, lookup-only migration).
