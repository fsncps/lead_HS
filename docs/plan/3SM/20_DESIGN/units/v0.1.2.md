# Unit v0.1.2 — Design delta: census close-out (full source probing, structured source reports, operator layer)

## Abstract

The Design for unit v0.1.2 — the census close-out that merges two
halves: completing the probe census for every register row and
delivering it as structured, decision-maker-usable reports (strategy
D26/D25), and the operator layer on top of the v0.1.1 `leadhs` tool

operator-layer delta from the 2026-09-11 morning pass, plus od8
(report content layer), od9 (census completion mechanics) and od10
(per-HS metrics via migration 0003) from the second pass of the same
day (CEO review, HOLD SCOPE). No new pipeline stages; the only
migration is the metric extension 0003; the design-ahead full-schema
migrations renumber 0004–0010 (docs-only — no files exist yet).

## Operator-layer delta (od1–od7; morning pass 2026-09-11)

### CLI contract deltas (od2–od4; binding via interfaces.md i10/i11)

- `main()` rewritten: `cli(standalone_mode=False)`;
  `click.exceptions.Exit` → its code; `UsageError` → 1 ("Error: …"
  + "Try 'leadhs --help' for help."); other `ClickException` →
  `exc.show()` + its code; `Abort` / `KeyboardInterrupt` → 130
  ("interrupted"); anything else → `bug:` + 1 (`LEADHS_DEBUG`
  re-raises). Commands keep `ctx.exit(n)`.
- All four groups gain `no_args_is_help=True` (bare `leadhs`, `db`,
  `source`, `probe` → help, exit 0).
- `list_` registered via `@source.command("list")`; the
  `source.add_command(list_, name="list")` line is deleted — one
  registration, the derived `list-` artifact is gone.
- `doctor`: the `--no-net` option is removed (was a no-op
  `default=True`); only `--net` remains (`doctor.main(rt, net=net)`).
- `--data-dir DIR` added to the root group: sets
  `db_path = DIR/leadhs.sqlite`; mutually exclusive with `--db`
  (`UsageError` → 1). The raw store follows `dirname(db_path)/raw`
  (`Runtime.store_root` unchanged).
- Unused `field` import dropped.

### DB initialization preflight (od3; interfaces.md contract)

`_ensure_initialized(ctx, rt)` in `cli.py`; called by `db status`,
`db audit`, `source load`, `source list`, `probe run`, `probe
record`, `probe report`. Checks: file exists and is non-empty, then
the `schema_version` table is present. On failure:

    error: database not initialized — run `make setup` (repo) or
    `leadhs db init` then `leadhs source load` first

Exit 1. `db init` is the only initializer and does not preflight.

### Makefile (full recipe text — od1, od5, od6)

```make
# lead_HS — operator entrypoint (v0.1.2). One target = one `leadhs` call;
# pipeline logic lives in the CLI (D21); make stays a thin wrapper.
# Parameters are make variables until M1 (committed config file).

.PHONY: help install doctor db-init db-status db-audit sources-load \
	sources-list setup probe-dry probe-single record report \
	report-publish probe census test smoke test-net clean clobber \
	frame sample acquire ingest parse analyze full
.DEFAULT_GOAL := help

PYTHON      ?= python3
DB          ?= data/leadhs.sqlite
MODE        ?= census
SAMPLE      ?= 5
SOURCE      ?=
REPORT_DIR  ?= data/report
PUBLISH_DIR ?= docs/report

export LEADHS_CONTACT
export LEADHS_DEBUG

LEADHS = leadhs --db $(DB)

help: ## self-documenting index
	@grep -hE '^[a-zA-Z_-]+:.*##' $(MAKEFILE_LIST) | \
	  sed -E 's/^([a-zA-Z_-]+):.*## *(.*)$$/  \1  \2/' | sort

install: ## editable install into the active interpreter
	$(PYTHON) -m pip install -e .

doctor: ## environment preflight
	$(LEADHS) doctor

db-init: ## apply pending migrations (backup taken by default)
	$(LEADHS) db init

db-status: ## applied/pending migrations, row counts
	$(LEADHS) db status

db-audit: ## provenance rules R1–R9 + raw-store orphans
	$(LEADHS) db audit --unreferenced

sources-load: ## upsert register from src/leadhs/dict/sources.csv
	$(LEADHS) source load

sources-list: ## list registered sources
	$(LEADHS) source list

setup: install db-init sources-load doctor ## first-run: install + init + load + doctor (idempotent)

probe-dry: ## census plan; zero network
	$(LEADHS) probe run --all --dry-run

probe-single: ## probe one source (SOURCE=CS-1)
	$(LEADHS) probe run --source $(SOURCE) --mode $(MODE) --sample $(SAMPLE)

record: ## manual finding (SOURCE= METRIC= VALUE=|VALUE_TEXT= [UNIT=] [URL=] [NOTE=])
	$(LEADHS) probe record --source $(SOURCE) --metric $(METRIC) \
		$(if $(VALUE),--value $(VALUE)) \
		$(if $(VALUE_TEXT),--value-text "$(VALUE_TEXT)") \
		$(if $(UNIT),--unit $(UNIT)) \
		$(if $(URL),--url "$(URL)") \
		$(if $(NOTE),--note "$(NOTE)")

report: ## render md/csv/json into $(REPORT_DIR)
	@mkdir -p $(REPORT_DIR)
	$(LEADHS) probe report --format md   --out $(REPORT_DIR)/probe-report.md
	$(LEADHS) probe report --format csv  --out $(REPORT_DIR)/probe-report.csv
	$(LEADHS) probe report --format json --out $(REPORT_DIR)/probe-report.json

report-publish: ## stage one report into $(PUBLISH_DIR) (WHICH=…; copies, never moves)
	@test -n "$(WHICH)" || { echo "report-publish: set WHICH=path/to/report" >&2; exit 1; }
	@test -f "$(WHICH)" || { echo "report-publish: no such file $(WHICH)" >&2; exit 1; }
	@mkdir -p $(PUBLISH_DIR)
	cp "$(WHICH)" "$(PUBLISH_DIR)/$$(basename "$(WHICH)")"
	@echo "staged $$(basename "$(WHICH)") into $(PUBLISH_DIR)/ — committing is explicit"

guard-%:
	@test "$(GO)" = "1" || { echo "$*: set GO=1 to confirm (GO=1 make $*)" >&2; exit 1; }

probe: guard-probe ## real census over all active sources (GO=1)
	$(LEADHS) probe run --all --mode $(MODE) --sample $(SAMPLE)

census: guard-census setup probe report db-audit ## setup → probe → report → audit (GO=1; guard runs before setup)

test: ## offline suite (net/mdbtools markers deselected)
	$(PYTHON) -m pytest

smoke: ## end-to-end fixture smoke (2am-Friday test)
	$(PYTHON) -m pytest tests/test_cli_smoke.py

test-net: ## opt-in real-network checks
	$(PYTHON) -m pytest -m net

clean: ## remove caches and build artifacts
	rm -rf build/ .pytest_cache/ .benchmarks/
	find . -type d -name __pycache__ -prune -exec rm -rf {} +

clobber: guard-clobber ## wipe local state (GO=1 + typed 'yes')
	@echo "clobber: this deletes the database and the raw store — type 'yes' to confirm"
	@read -r confirm; test "$$confirm" = "yes" || { echo "aborted"; exit 1; }
	rm -f "$(DB)" "$(DB)-wal" "$(DB)-shm"
	rm -rf data/raw data/backups $(REPORT_DIR)

# M1–M4 stubs — fail loudly with a pointer (strategy U6)
frame sample acquire ingest parse analyze full:
	@echo "error: '$@' is milestone-gated (M1–M4) — see 10_STRATEGY/ARCHITECTURE.md rollout" >&2
	@exit 1
```

Key semantics: `guard-%` is a **prerequisite**, so it fires before any
recipe side effect; `census` lists `guard-census` first, so `setup`
(pip install) never runs without GO=1. All recipe values are
shell-quoted. `report-publish` copies and prints the commit reminder
(U5). `.gitignore` gains `build/`, `.pytest_cache/`, `.benchmarks/`.

## Census completion mechanics (od9)

- **CS-2 (Comext DS-045409):** the adapter builds a parameterized
  JSON query on the register's base URL — documented constants
  (format, frequency, period, flow, product) with defaults fixed in
  the design; exact values are pinned at census execution (strategy
  OPEN item) and land in `run.parameters_json`; the response is
  archived as a document (verification artifact). Per-HS queries
  emit `records_hs3208/3209/3213` (method=api); an empty result set
  is an honest 0. The bare-URL fetch (the export_rows=1 artefact) is
  retired.
- **ST-2 (SPIN):** register URL fixed to the download page
  (`?page_id=54`, matching the ST adapter's hints). Reachability
  re-checked at execution; persistent failure stays a `failed` run
  with notes, plus a manual census_status record if needed.
- **PE catalog-level depth:** after the landing page, the adapter
  fetches up to 3 category pages (from the enumerated category_list;
  polite spacing unchanged) and emits `category_count` per category
  (value_text = category path — vocabulary semantics unchanged);
  `catalog_count` stays landing-page-derived with a notes line;
  product-page sampling (sample_n) unchanged. A failing category
  page appends a note and continues (sample-page pattern).
- **Manual records:** ST-1 PCN aggregates, PE-3 deferral note, and —
  if manual review is needed — CS-1 export mechanics are recorded
  via `make record` / `probe record` with metric `census_status`
  (method=manual). `probe record` works on inactive sources (ST-1).
- **Blocked/failed visibility:** the engine already writes run
  status + notes; the report content layer (od8) is what makes them
  visible.

## Report content layer (od8)

One assembly in `report.py`, three renderers — same data (D25), DB
reads only (P7). Fetchers:

- `_fetch_sources` — the register (source table): id, class, name,
  url, access_method, verification_status, active, notes.
- `_fetch_latest_runs` — latest census probe run per source (single
  GROUP BY on `run.id`; any status) with status_code, finished_at,
  notes, document/finding counts. Dry-run runs are excluded
  (`parameters_json.dry_run` parsed in Python; malformed JSON →
  treated as a real run — fail open toward inclusion).
- census (`v_probe_latest`), anchors (`v_anchor_candidates`),
  activity (`v_source_activity`) — existing views unchanged.

Per-source dict: identity / access / content / counts / availability
/ provenance / run-status. Renderers:

- **md** — the decision-maker document:
  - Title "Source feasibility census report" + framing paragraph
    (source-feasibility metrics; product and lead prevalence are M2+
    deliverables, never implied here — U9). Product data only
    (Strategy MASTER D27): LG register rows appear solely as
    inactive rows in the matrix — no legal content, no findings.
  - Summary matrix: one row per registered source (all 14, active
    flag included); columns: status, format, granularity,
    coverage_years, free_access, export_rows, records_hs3208/3209/
    3213, catalog_count, category_count, page_sample_ok,
    sds_sample_ok, last run_key.
  - Per-source sections (identity/access/content/counts/availability/
    provenance); duplicate same-run metric rows (per-category
    category_count) listed in full.
  - Run status table: latest census run per source — **including
    blocked/failed with their notes**.
  - Anchor candidates + source activity (footnote: raw counts, dry
    runs included there).
  - Legend: "—" = metric absent (not queried); `0` = queried,
    empty; metric values cite their done run's run_key; status
    reflects the latest census run.
- **csv** — the summary matrix only (the spreadsheet deliverable;
  json carries the full data — no duplication).
- **json** — the full structure (stable shape; the future M3/M4
  report build consumes the same assembly).

  UsageError → 1; Abort/interrupt → 130; Exit → its code).

  `bug:`.
- od4: `source list` single registration; `--no-net` removed; groups
  `no_args_is_help`; `--data-dir` exclusive with `--db`.
- od5: report routing via make — intermediates `data/report/`,
  `report-publish` copies to `docs/report/`.
- od6: `.gitignore` additions (build/, .pytest_cache/, .benchmarks/).
- od7: tests — operability, preflight, make-wiring (`-n`/guarded
  only); wheel-build verification in-unit.
- od8: report content layer — one DB-only assembly, three renderers;
  csv = summary matrix only; run status + notes visible incl.
  blocked/failed; dry-runs excluded; matrix covers all registered
  sources; legend "—" vs 0; framing per U9.
- od9: census mechanics — parameterized CS-2 query (params recorded,
  response archived), ST-2 register URL fix, PE category depth ≤ 3

- od10: per-HS counts as explicit metric codes records_hs3208/3209/
