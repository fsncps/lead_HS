# Unit v0.2.0 — Design delta: market scale & data availability (the numbers unit)

## Abstract

The Design for unit v0.2.0 — the numbers unit (strategy
`10_STRATEGY/v0.2.md`, the D31 turn). The unit delivers the
numbers-first report: **N1** (paints on the EU market — estimate in
magnitudes from official statistics), **N2/N3** (data availability —
access tiers per source, counted where sources expose counts). Method
bounds: no scraping — reconnaissance only (robots/terms, sitemap
product-URL counts via a bounded structured fetch, manual-web);
EU-only; catalog walks stay deferred (V4 — machinery idles). The unit
rides the built machinery (V9): od8 report content layer, probe
engine + adapter contract, metric-vocabulary extension by migration
INSERT, make operator layer with GO=1 discipline. It **absorbs** the
un-built v0.1.3 groundwork it needs (source-load validation pe6,
enumeration register model pe1, priors metric migration 0005 pe2 —
B8/D26/d31 absorption precedent) and **supersedes** the v0.1.3 walk
execution (i14 walk-floor aggregate sections defer, spec stays on
file for the scraping-go unit).

## ENG review (2026-09-12, mode BIG CHANGE)

Findings e1–e8, all folded into the nu items before build:

- **e1 (chain vs exit 2, decision 1A):** the chained make targets
  (`census`, new `recon`) abort on the *expected* sweep exit 2
  (some site blocked/failed — findings persisted). The probe step
  inside the chains tolerates exactly exit 2 (`|| test $$? -eq 2`);
  any other failure still aborts.
- **e2 (JSON-stat shape, decision 2A):** Eurostat Comext returns
  JSON-stat — `value` is an object keyed by flat row index, not a
  list; the existing `_rows_of` list heuristic would silently
  count 0. One query per HS with partner as the only free
  dimension; a minimal one-dimension decoder (flat index → partner
  via id/size) yields sums AND partner tops from the same archived
  payload. General JSON-stat reader → TODOS (PRODCOM/SBS are
  future callers).
- **e3 (response-size bound, decision 3A):** the fetch seam gains a
  per-call `max_bytes` streaming cap (typed `SizeLimit` error →
  recon notes it, counts 0, "floor partial"); recon passes ~25 MB;
  census/ST stay uncapped (the SPIN .mdb is legitimately ~100 MB).
- **e4 (gzip sitemaps):** `.xml.gz` payloads are sniffed via magic
  bytes and decompressed (stdlib `gzip`) before parsing — raw gzip
  would be misreported as malformed XML.
- **e5 (XML namespaces):** `<urlset>`/`<sitemapindex>` children are
  namespaced; counting iterates local names (strip the `{…}` prefix)
  — a naive `find("loc")` is a silent-0 trap.
- **e6 (robots policy "unknown"):** robots fetch network error →
  policy "unknown" → recon proceeds with a note; only an explicit
  disallow blocks.
- **e7 (edge mechanics):** a sitemap-index child that is itself an
  index is noted, not recursed; CS-2 year resolution steps back on
  an empty result (max 3 tries, then a document-blocked note), the
  resolved year pinned in parameters_json; the CS-2 dry-run also
  plans the sum-query URLs (i7 stays honest for the new fetches).
- **e8 (record mode label):** `record_manual` hardcodes mode
  "census" (engine.py) — gains a mode parameter (CLI `--mode`,
  default census) so recon-era manual records
  (`sds_library_visible`) are labeled honestly.
- PHASE06 matrix column fix: `census_status-walk_note` → plain
  `census_status` (walk machinery idle, V4; block reasons live in
  the status value_text).

## Recon machinery (nu1)

- **probe_mode `recon`** (0006 INSERT): `probe run --mode recon`
  (CLI choice list gains the value; no new command — V9 intact).
- **PE adapter recon branch** (dispatch on ctx.mode inside
  PEAdapter.probe — no new adapter class): (1) robots.txt fetch —
  existing robots/terms findings and RobotsDisallowed mapping;
  absent robots (404) = allow-all (existing rule); (2) sitemap
  discovery from robots `Sitemap:` lines, else `/sitemap.xml`;
  (3) structured fetch, **counts only — no URL harvesting**; the
  sitemap bytes archive as a document (R2/R3 hold); (4) product-URL
  counting via stdlib `xml.etree.ElementTree` (lxml is outside the
  pure-Python stack, D24): `<loc>` entries matching the site's
  product-URL pattern — pattern token `product_pattern=` in the
  enumeration notes convention (i13 extension, same stringly
  acceptance), generic fallback heuristics (`/product`, `/p/`,
  case-insensitive); pattern and fallback use recorded in the
  finding notes (category_count precedent — numeric metric, notes
  carry semantics, R4 strict).
- **Bounded index expansion (1A):** a `<sitemapindex>` response
  triggers fetching child sitemaps up to a hard cap of **5**
  (robots-compliant, same counts-only rule); a cap hit flags the
  floor in the finding notes ("index, K children fetched, cap 5 —
  floor partial"). Single-file sites: exactly one fetch. A child
  that is itself an index is noted and not recursed (e7).
- **Well-formed-input defenses (e3/e4/e5):** sitemap fetches carry
  a per-call streaming size cap (~25 MB, typed `SizeLimit` → note,
  count 0, "floor partial"); gzip payloads (`\x1f\x8b` magic) are
  decompressed before parsing; tag matching iterates local names,
  namespace-agnostic.
- **Shadow paths:** no sitemap declared and /sitemap.xml 404 →
  `sitemap_products` = 0, note "no sitemap"; empty `<loc>` set or
  zero pattern matches → 0 (legend: 0 = queried-empty, never "—");
  malformed XML → `ParseError` → `format` finding (WARNING, manual
  review), run done; network error → `ProbeNetworkError` → run
  failed (exit 2); robots disallow → `robots_denied` + run blocked
  (exit 2); robots unreachable → policy "unknown" → proceed with a
  note (e6). All rows of the existing exception table — no new
  exception classes.
- **`sitemap_products`** (numeric, count) — 0006 INSERT; joins
  v_anchor_candidates (0006 redefinition — floors entered the view
  since 0004's products_listed; access floors, not population
  anchors — promotion stays manual, D20).

## Trade aggregation (nu2)

- **CS adapter census branch extension:** after the existing per-HS
  parameterized queries (records_hs* unchanged), run the full-year
  aggregation query per HS heading × flow=import (flow pinned in
  run parameters_json), parse the JSON-stat response, and record
  sums: **`trade_kg_hs3208`, `trade_eur_hs3208`,
  `trade_kg_hs3209`, `trade_eur_hs3209`** (numeric; records_hs*
  precedent — HS in the code, not in notes). 3213 stays rows-only
  (context, V7). Supplementary units and partner tops ride in
  finding notes; the raw JSON archives as a document (payload can
  be large — linear sums only).
- **JSON-stat decode (e2, decision 2A):** one aggregation query per
  HS with partner as the only free dimension; a minimal decoder
  maps the flat `value` index to partner labels via `id`/`size`
  (row-major over the declared dimension order) — sums and partner
  tops both come from the same archived payload; no general
  JSON-stat reader in this unit (TODOS).
- **Latest-year fallback (e7):** requested year empty → step back
  one year, max 3 tries, each noted; exhausted → document-blocked
  census_status note; the resolved year is pinned in
  parameters_json. Empty result = honest 0 (existing rule); layout
  change → `UnexpectedFormat` → `format` finding (existing
  mapping). The dry-run also plans the aggregation query URLs
  (i7).

## AS-class register model (nu3)

- **source_class AS** (0006 INSERT). AS rows enter the register
  (sources.csv) only with a pinned real URL (url NOT NULL);
  candidates without a confirmed URL stay documentation-level OPEN
  items (V6 — discovery first-class, documented growth only).
- **Activation semantics:** manual-web sources ship `active=0`
  (ST-1 precedent) — `probe run --all` sweeps only fetchable
  sources; counts land via `make record` (manual runs work on
  inactive sources). Fetchable AS rows (e.g. a register with a
  public statistics download) may enter active=1 and ride the ST
  adapter's treatment by class dispatch — decided per row at
  discovery, recorded in the CSV batch note.
- **`producers_registered`** (numeric, count) — 0006 INSERT. N1
  industry-structure counts (CEPE members, SBS enterprises) ride
  THIS metric; **N2 sums only `products_registered`** (product-unit
  counts: SPIN preparations, PCN formulations, national register
  products). Mixing producer counts into N2 is a forbidden
  arithmetic error; the separation lives in the metric codes, not
  in notes (od9 R4 lesson).

## Numbers-report layout (nu4)

Extensions to the od8 content layer (one DB-only assembly, three
renderers — i12 unchanged):

1. Framing (unchanged): source-feasibility ≠ product/lead counts.
2. **N1 headline block (md):** the market-size range from the
   method sheet (nu5) + the anchor values rendered from the DB
   (trade sums, producers_registered, products_registered).
3. **N2/N3 headline block:** totals with **tier composition** —
   per active source: tier (a) dataset/register access counted
   (latest done `products_registered`), (b) sitemap-visible counted
   (latest done `sitemap_products`, cap flags inline "≥, index-cap
   limited"), (c) visible but uncounted without scraping
   (characterized, no counts), (d) blocked/unknown (latest run
   blocked/failed, or nothing recorded). N2 = Σ tier (a)+(b)
   counts; N3 = counted where sources expose doc-bearing counts +
   the count of `sds_library_visible` = 1 sites (site count,
   labeled as such — no false precision, V1/V2). Excluded-and-
   counted line (i14 inclusion semantics carried: active sources,
   latest done runs only); zero-states render explicit lines
   ("no counted sources yet" — never a bare 0).
4. **Per-source matrix** (all registered sources; inactive rows
   visible, never in sums): columns gain `tier`, `sitemap_products`,
   `sds_library_visible`, `products_registered`,
    `producers_registered`, `trade_kg/eur_hs3208/3209` (CS rows),
    `census_status` (plain — no walk column; the walk machinery is
    idle, V4, and block reasons live in the status value_text).
5. **Trade-context lines:** one compact line per CS source
   (import sums, latest year, partner tops from notes).
6. **Priors lines:** one line per ST/AS source
   (products_registered / producers_registered / census_status).
7. **Access-decision bridge (md only):** per channel — what a
   scraping go would buy (tier (c) size, blocked sites) and cost;
   qualitative, evidence-cited (i14 bridge semantics, stripped of
   walk-floor inputs).
8. Execution log + legend (unchanged mechanics).

csv: matrix columns as above; json: full structure incl. tier dicts,
excluded-source lists, anchor values. **Deferred (not built):** the
i14 walk-floor aggregate sections — zero done walks exist; the spec
stays on file for the scraping-go unit.

## N1 assembly contract (nu5)

The N1 range is stated in a **hand-maintained method sheet** inside
the report's md framing (like the bridge — analytic choices live in
prose, D27 documentation-layer precedent): per anchor — source,
coverage, formula, caveats, assumption bounds (e.g. products-per-
producer range) with provenance (URL + access date). The assembly
renders the DB-cited anchor values; the range arithmetic itself is
md-only. json carries anchor values, not computed ranges (P7:
user-facing counts from the DB; the estimate stays labeled as an
estimate, V2).
