# Unit v0.2.4 addendum (D40) — Design delta: BASTA special probe (`leadhs probe basta-probe`)

## Abstract

Design for the D40 addendum (strategy §"Addendum — BASTA special
probe", `10_STRATEGY/v0.2.4.md`). One new probe command pins an
anonymous search route behind the BASTA online client shell
(bastaonline.se /sok), characterizes data availability and structure
(count, field schema, identity completeness), and delivers a seeded
random sample of 100 articles as CSV with the identity tuple
(manufacturer + product ident) and the category proxy (BK04/BSAB).
No schema change: the addendum reuses the engine write path
(migration-level extension only for its probe_mode + metric lookup
codes, same path as migration 0010). Pool method, fallbacks and the
auth-route outcome are all explicit, honest, and offline-testable.

## Command surface

    leadhs probe basta-probe
        [--n 100]                  # sample size (default 100)
        [--seed 42]                # seeded draw; recorded in run + CSV
        [--out-dir data/report]    # D22 routing
        [--dry-run]                # plan requests; zero network

Make target `basta-probe` (GO=1 gated), following the existing
`as-probe` pattern.

## State machine (review 1A — always truth-telling)

    pending ──▶ delivered          (basta_special_rows; exit 0)
         ────▶ unavailable-mech    (basta_special_unavailable: no route found / auth route / pool < n; exit 0)
         ────▶ failed              (network failure on pinned URLs only; exit 2)

## Module placement

- New module `src/leadhs/probe/basta_probe.py` — imports the shared
  machinery (`engine._insert_run/_finish_run/persist`,
  csv_sample's `PROVENANCE_COLUMNS`/`_write_sample_csv` draw-and-csv
  mechanics, `sniff_kind`), zero duplication.
- CLI slot in `src/leadhs/cli.py` `probe` group; Makefile target.
- Constants (db discipline — all pinned here, never computed):
  - db1 base URLs (www.bastaonline.se, Landing /sok path, robots path)
  - db2 discovery budget (≤5 polite GETs for the bundle chain)
  - db3 pool threshold (20,000 rows — above it, random-page method)
  - db4 draw seed default (42) and n (100)
  - db5 paint-filter mechanism (`bk04`/`bsab` param + its enumerated
    values from the pin stage; used only if both the param and the
    values pin cleanly)
  - db6 article-page field schema (name, article number, BK04, BSAB,
    GTIN, RSK, E-number, BASTA ID, grade, company, eBVD content)
  - db7 auth-route + agreement-route wording for the why-not record
- Lookup-seed migration (0011): probe_mode `basta_special_probe` +
  metrics `basta_special_rows` / `basta_special_unavailable`
  (engine vocabulary path, no schema change).

## Pool method (db3, decision 2C)

Full paint-subset pagination up to db3 rows → `random.Random(seed)`
sample over the canonically-ordered distinct-article pool (D2);
above the threshold, or if db5 is unreliable: seed-fixed
random-page draws (honest `pool≈unknown`), or all-articles + category
column as the last fallback. The method actually used is recorded in
the finding notes and a CSV provenance column. Shortfall (pool < n)
is recorded, never padded (same semantics as D36 `csv_sample_rows`).

## Fetcher change (decision 4B)

`Fetcher._wait_for_spacing` reads the robots crawl_delay (already
parsed by `RobotFileParser`) for the domain and uses
`max(min_spacing, crawl_delay)` — capped at the existing
`rate_limit_cap`. One new unit test (fixture robots + stubbed
clock/sleeper asserts the 10 s wait). No API change; existing
callers unaffected (BASTA is the only registered source with a
crawl-delay today).

## Test plan (offline only)

Fixture-site routes (tests/conftest.py `_FixtureSite`): shell page
with asset links; bundle snippet carrying the pinned route (and a
companion.json payload); auth-gated 401 route; paint-filtered and
unfiltered JSON bodies; robots.txt with `Crawl-delay: 10`.
Cases: pin-found/delivered; pin-not-found → unavailable-mech;
401-on-route → unavailable-mech; network failure → failed exit 2;
filter-reliable vs fallback; threshold split (2C both branches);
shortfall note; CSV layout (verbatim + provenance block); seeded
reproducibility (same seed same rows); migration seed-sync test.
Run count target: ≥12 new offline tests, suite stays fully offline.
